# 12 · 版本管理与发布清单

> 这份文档只解决一件事：**每次发版，哪些地方必须跟着改，哪些地方绝对不能动。**
>
> 发版前先读这里。`npm run check:version` 不通过，不许打包、不许上传。

---

## 1. 唯一版本源

`package.json` 的 `version` 是**唯一**版本来源。

```
package.json version
  ├── 主进程 app.getVersion()        → 窗口 / 关于面板
  ├── 渲染进程 ipc.app.info().version → 工作台、设置
  ├── electron-builder artifactName   → Moqi-<version>-Setup.exe
  ├── after-pack.js                   → exe 文件属性
  └── Windows 应用列表 / 卸载程序
```

- 渲染进程**不许**写死版本号，只许 `ipc.app.info()`。
- README、Release 说明、AGENTS 都是“副本”，必须手动同步；`scripts/check-version.js` 负责抓漏。
- 安装包文件名、exe 属性、Windows 应用列表都由 electron-builder / after-pack 自动带版本，不需要手改。

---

## 2. 版本号怎么定

| 这次改了什么 | 版本动作 | 例子 |
|---|---|---|
| 新功能、新界面、新入口（数据兼容） | **MINOR +1** | 0.9.1 → 0.10.0 |
| 修 bug、文案、样式、性能（不改数据） | **PATCH +1** | 0.9.1 → 0.9.2 |
| 数据/存储结构不兼容，需要迁移 | **MAJOR**（或 MINOR + `dataVersion`） | 1.0.0 |
| 只改 README / docs / 注释 / 测试，不重新打包 | **不升** | 直接提交 |
| 只改 Release 说明（补一句话、改错字） | **不升** | 直接改 Release |
| 已经发布过，又重新打包同一个版本 | **禁止** | 必须升 PATCH |

判断标准只有一句：**用户下载到的二进制有没有变。**
变了就升版本；只改说明就不升。

---

## 3. 每次发版必改（硬清单）

| # | 文件 / 位置 | 改什么 | 谁检查 |
|---|---|---|---|
| 1 | `package.json` | `version` | `check:version` |
| 2 | `package-lock.json` | 跑 `npm install --package-lock-only` | `check:version` |
| 3 | `README.md` | 「最新改动」标题、下载区「当前版本」、4 个下载链接、文件大小 | `check:version` |
| 4 | `docs/releases/vX.md` | 新建发布说明 | `check:version` |
| 5 | `docs/CHANGELOG.md` | 顶部新条目 | `check:version` |
| 6 | `AGENTS.md` | 顶部版本、打包发布行、`release/` 行、状态表 | `check:version` |
| 7 | `release/` | `Moqi-X-Setup.exe` + `Moqi-X-portable.7z` | `check:version -- --assets` |
| 8 | GitHub / Gitee Release | 同 tag、同文件名、同说明 | 人工 |
| 9 | `docs/screenshots/` | UI 或版本显示变了就重拍 | 人工 |
| 10 | 安装包元数据 | 装完看 exe 属性 / 关于面板 | 人工 |

### 3.1 README 的四个链接

下载区必须同时有 Gitee 和 GitHub、安装版和绿色版，四处版本号一致：

```
https://gitee.com/azs_A/MoQi/releases/download/vX/Moqi-X-Setup.exe
https://gitee.com/azs_A/MoQi/releases/download/vX/Moqi-X-portable.7z
https://github.com/keziea/MoQi/releases/download/vX/Moqi-X-Setup.exe
https://github.com/keziea/MoQi/releases/download/vX/Moqi-X-portable.7z
```

`check:version` 会扫 README 里所有 `releases/download/v.../`，**只允许出现当前版本**。

### 3.2 AGENTS 的三处

1. 顶部：`> 最后更新：YYYY-MM-DD · 版本 vX`
2. 状态表「打包发布」行：`✅ vX 安装包（…MB）与绿色版（…MB）已构建…`
3. 文件职责表 `release/` 行：`（当前 vX）`

### 3.3 截图

- 工作台 / 阅读页截图里会显示版本号；发版后如果 UI 或版本胶囊变了，重跑：
  ```bash
  npm run build
  env -u ELECTRON_RUN_AS_NODE ./node_modules/.bin/electron scripts/capture-screens.js
  ```
- 脚本用隔离的临时 userData，**不会碰真实书库**。
- README 首屏用的是 `docs/screenshots/05-home.png`；`09-about.png` 是「关于」面板。
- 截图里的版本号必须等于 `package.json`。只改文档、不重打包时不用重拍。
- README 的截图 URL 带 `?v=X`（如 `05-home.png?v=0.9.1`）；发版时一起改，用来破 jsdelivr 对 `@main` 的缓存。`check:version` 会检查这个参数。

## 4. 绝对不要跟着改

| 东西 | 为什么 |
|---|---|
| `Settings.dataVersion` | 只有设置结构变了才升；普通发版不动 |
| 代码里的「v0.8 单根布局」 | 这是**布局版本**，不是 app 版本；改了会误导迁移逻辑 |
| 旧 `docs/releases/v*.md` | 历史发布说明，不改 |
| 旧 `docs/CHANGELOG.md` 条目 | 历史，不改 |
| README「上一版 / 更早」段落 | 历史，不改 |
| 数据目录名 `MoQiReader / Program / Data` | 改了老用户数据找不到 |
| 旧 Git tag、旧 Release 附件 | 不覆盖、不删除（配额例外见 §7） |
| `copyright` 年份 | 除非跨年 |

> 一句话：**版本号是“这次发布”的编号，不是“整个项目所有历史”的编号。** 历史段落保留旧版本号是正常的。

---

## 5. 什么时候不用升版本

- 只改 README、`docs/`、代码注释、测试、CI，**且不重新打包**。
- 只改 Release 说明（补一句、改错字、换截图链接）。
- 只改 `.gitignore`、issue 模板、仓库描述。

这些直接提交即可；如果改了 README 的下载链接 / 版本说明，仍然要跑一次 `check:version` 确认没有写错当前版本。

---

## 6. 发版 10 步

1. 读这份文档。
2. 改 `package.json` → `npm install --package-lock-only`。
3. 写 `docs/releases/vX.md`、`docs/CHANGELOG.md`、README、AGENTS。
4. `npm run check:version` —— 必须全绿。
5. `npm test` —— 117 + 29 + 14 全过。
6. 需要新截图就重拍 `docs/screenshots/`。
7. `npm run dist`（安装版）+ `npm run pack`（绿色版）；再跑 `npm run check:version -- --assets`。
8. 上传 GitHub / Gitee Release（同 tag、同文件名、同说明）。
9. 推送代码 / README 到两端；验证下载链接、顶部按钮跳转、关于面板版本。
10. 更新 AGENTS / memory；撤销临时令牌。

---

## 7. Gitee 附件配额（1GB）

- 每个版本两个包约 **145MB**，1GB 最多放约 **7 个版本**。
- 发新版前先算一下：`GET /repos/azs_A/MoQi/releases/{id}/attach_files`，把 `size` 加起来。
- 不够时，**优先删最老版本的安装包附件**，保留 tag、源码、Release 说明；GitHub 上的旧版不动。
- 不要删当前版本和上一版的附件。
- 删除附件前先在对话里说明删了哪两个版本，避免用户找不到旧版。

---

## 8. 用户从哪看到版本

| 位置 | 显示 |
|---|---|
| 工作台右上角 | `vX` 胶囊，点击打开「关于墨栖」 |
| 工作台左侧栏底部 | `vX`，可点击 |
| 阅读设置底部 | `关于墨栖 · vX` |
| 关于面板 | `vX` + Electron / Chromium / Node + 系统 + 数据目录 |
| Windows 应用列表 / exe 属性 | 文件版本 `X` |
| 安装包文件名 | `Moqi-X-Setup.exe` |
| README / Release | `vX` |

关于面板**不自动联网检查更新**（软件是离线的）；它提供 GitHub / Gitee 发行版入口，用户自己去对比。

---

## 9. 给 AI 的硬规则

1. 动版本之前先读这份文档。
2. UI 里不许出现写死的 app 版本号；只许 `app.getVersion()` / `ipc.app.info()`。
3. 发版前 `npm run check:version` 必须通过；`predist` / `prepack` 会自动跑。
4. 不许覆盖已经发布过的同版本安装包；重新打包就升 PATCH。
5. 只改文档不要乱升版本；改了代码 / 打包内容就必须升。
6. 发完版更新 AGENTS、CHANGELOG、README，并写 `.workbuddy/memory/`。
7. 删除 Release 附件前，先确认配额、保留策略，并在回复里说明。

---

## 10. 检查脚本做了什么

`scripts/check-version.js` 只读、不改文件：

- `package.json` 版本格式
- `package-lock.json` 顶层 / `packages[""]`
- README：「最新改动」标题、「当前版本」、发布状态行、四个下载链接、链接版本唯一
- AGENTS：顶部版本、发布状态
- CHANGELOG：顶部 4000 字内含当前版本
- `docs/releases/vX.md` 存在
- `src/pages/Workspace.tsx` 没有硬编码 `v0.x.y`
- `--assets`：`release/Moqi-X-Setup.exe` / `-portable.7z` 存在且非空

任何一项失败都会以非 0 退出，`npm run dist` 会被 `predist` 拦住。

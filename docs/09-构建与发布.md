# 09 · 构建与发布

## 1. 环境要求

| 项 | 要求 |
|---|---|
| Node.js | ≥ 20（本项目在 22.22.2 验证） |
| npm | ≥ 10 |
| 系统 | Windows 10 / 11 x64 |
| 磁盘 | 约 1.2GB（含 node_modules 与 Electron 二进制） |

## 2. 常用命令

```bash
npm install          # 安装依赖（首次；Electron 二进制较大，耐心等）
npm run dev          # 开发模式（Vite + Electron 热更新）
npm run build        # 编译渲染层与主进程
npm run dist         # 打包 Windows 安装包 → out-app/
npm run pack         # 生成绿色版目录（默认 ~/Moqi-portable/MoQiReader）
npm test             # typecheck + 117 旧布局 + 29 新布局 + 14 安装器路径测试
npm run test:single-root # 只跑 v0.8 单根布局/迁移/收书测试
npm run test:ui          # 打包版 UI 回归：删掉最后一本书回到空书架（需先 dist）
npm run test:installer   # 只跑安装器路径逻辑（需先跑过一次 dist 以取得 NSIS）
```

## 3. 开发模式原理

```
concurrently
  ├─ vite                 → http://localhost:5173
  └─ wait-on 5173 && tsc -w && electron .
```

`electron/main.ts` 通过 `process.env.VITE_DEV_SERVER_URL` 判断是否加载 dev server。

## 4. 打包配置要点

`electron-builder.yml`：

```yaml
appId: com.moqi.reader
productName: 墨栖
directories:
  output: out-app
files:
  - dist/**
  - dist-electron/**
  - package.json
win:
  target: nsis
  icon: build/icon.ico
nsis:
  # ★ 必须显式关掉一键安装；目录页由自定义页接管
  oneClick: false
  allowToChangeInstallationDirectory: false
  perMachine: false
  allowElevation: true
  createDesktopShortcut: true
  createStartMenuShortcut: true
  shortcutName: 墨栖
  include: installer.nsh   # 自定义「数据存放位置」页
  artifactName: Moqi-${version}-Setup.${ext}
  deleteAppDataOnUninstall: false
```

**注意事项：**

1. 主进程用 `tsc` 编译到 `dist-electron/`，**不要用 esbuild bundle** —— `pdfjs-dist` 有 worker 文件路径依赖，bundle 后会找不到。
2. `pdfjs-dist` 的 worker 需要在主进程里显式指定：
   ```ts
   import { createRequire } from 'module';
   const require = createRequire(import.meta.url);
   pdfjsLib.GlobalWorkerOptions.workerSrc =
     require.resolve('pdfjs-dist/legacy/build/pdf.worker.mjs');
   ```
3. `asar: true` 时，`pdfjs` 的 cmaps / standard_fonts 需要 `asarUnpack`：
   ```yaml
   asarUnpack:
     - node_modules/pdfjs-dist/**
   ```
4. 应用图标：`build/icon.ico`（256×256，多尺寸）。缺失时用 Electron 默认图标（J4 验收不过）。
5. **安装器必须让用户选路径。** `oneClick` 不写就是 `true`，会一键装进 `C:\Users\<用户名>\AppData\Local\Programs\moqi-reader`，用户既不能换盘也找不到装哪了（v0.4.0 就是这个问题）。必须显式写 `oneClick: false` + `allowToChangeInstallationDirectory: false` —— 目录页由 `build/installer.nsh` 的自定义「同页双路径」接管，不再用 electron-builder 自带页。
6. `artifactName: Moqi-${version}-Setup.${ext}` 让产物直接命名成 `Moqi-0.4.1-Setup.exe`，省掉手工改名，也保证和 README 里的下载链接一字不差。
7. `deleteAppDataOnUninstall: false` —— v0.8 卸载只删 `Program`，默认保留旁边的 `Data`。阅读进度、笔记、统计都在 `Data` 里，不能跟着程序一起没。
8. **本项目故意设 `signAndEditExecutable: false`，改由 `scripts/after-pack.js` 调 rcedit 写图标与产品信息。** 原因：electron-builder 自带的 exe 改写依赖 winCodeSign 缓存包，包内 macOS 符号链接在普通 Windows 账户解压会因「客户端没有所需的特权」失败。效果必须一致：桌面快捷方式与 exe 本身的图标、`ProductName`、`CompanyName` 都要正确；打包后检查 `out-app\win-unpacked\墨栖.exe` 的版本信息，`ProductName` 应为 `墨栖`、`CompanyName` 应为 `Moqi`。没有签名证书时仍会跳过签名（日志 `no signing info identified`），这是正常的。
9. 验收图标是否真的写进去了：打包后看 `out-app\win-unpacked\墨栖.exe` 的版本信息，`ProductName` 应该是 `墨栖`、`CompanyName` 应该是 `Moqi`；如果还是 `Electron` / `GitHub, Inc.`，说明第 8 条又被关掉了。

10. **安装器是 v0.8 单输入自定义页**，在 `build/installer.nsh`，通过 `nsis.include` 引入。它注册**一个** `Page custom MoqiPathsPageCreate MoqiPathsPageLeave`（`customPageAfterChangeDir`），只让用户选一个上级目录：
    - 选 `D:\` → `D:\MoQiReader`；选 `D:\Apps` → `D:\Apps\MoQiReader`；选到 `MoQiReader` 本身不再套一层。
    - 安装器自动创建 `<MoQiReader>\Program` + `<MoQiReader>\Data`，并写 `Data\.moqi-data`；`$INSTDIR` 是 `...\MoQiReader\Program`。
    - 浏览选中后，框里直接显示最终 `MoQiReader` 目录，不再有第二个数据输入框或下方预览行。
    - 路径超过 240 字符、含 `< > " | ? *`、Program Files / Windows / 系统盘根 → 阻断。
    - 升级只覆盖 `Program`，`Data` 不动；卸载默认保留 `Data`，勾选并二次确认才删。
    - 旧版程序在 `MoQiReader\墨栖.exe` 时，新版装到 `Program` 子目录；旧根目录文件可安装后手动删除，数据由首次启动迁移。
    - 自写的 include 会**先于** `installer.nsi` 里的 `MUI2.nsh` 被处理，所以文件头必须自己 `!include "MUI2.nsh"`，否则 `MUI_HEADER_TEXT` 找不到。
    - 页面函数要包在 `!ifndef BUILD_UNINSTALLER` 里；卸载器那一趟用 `UninstPage custom` 注册自己的数据删除页。否则 NSIS 会报 `warning 6010 ... not referenced`，被 electron-builder 当错误。
11. 改完 `installer.nsh` 必须真的跑一次 `npm run test:installer` + `npm run dist`。`test:installer` 会真编 NSIS、真运行路径函数，能抓到 `GetFileName` 参数顺序、路径追加这类 `tsc` 看不出来的问题；`test:single-root` 则验证 `Program`/`Data` 推导、旧数据迁移和收书。`dist` 验证完整安装器/卸载器能编译。NSIS 的错误只在打包时暴露（`macro named ... not found` / `warning treated as error`），`npm run build` 看不出来。本机打包时 electron-builder 裁剪语言包会批量删 `.pak`，若遇到 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`，用 `CODEBUDDY_SAFE_DELETE_ENABLED=0 npm run dist` 只对这一次构建放开中间产物的删除保护。

## 5. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `Electron failed to install correctly` | 二进制下载失败 | 设 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 后重装 |
| 白屏 | 主进程加载 URL 错误 / preload 路径错 | 检查 `dist-electron/electron/preload.js` 是否存在 |
| `require is not defined` | 主进程被当成 ESM | 主进程 `package.json` 的 `type` 必须为 `commonjs`（或 tsconfig 输出 CJS） |
| PDF 打开报 `worker` 错误 | workerSrc 未指定 | 见 §4.2 |
| 中文书名乱码 | TXT 编码判断错 | 检查 `chardet` 结果，强制 GB18030 兜底 |
| 打包后字体不对 | 系统缺字体 | 字体栈已带 fallback，属正常差异 |
| `dist` 卡在下载 | nsis 资源下载慢 | 设 `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/` |

### 5.1 真实踩过的坑（本项目验证）

**① `npx electron` 以 Node 模式启动，报 `protocol` undefined**

现象：`TypeError: Cannot read properties of undefined (reading 'registerSchemesAsPrivileged')`，堆栈里是 `node:internal/modules`。

原因：环境里存在 `ELECTRON_RUN_AS_NODE=1`，Electron 把自己当 Node 跑，`require('electron')` 返回的是 npm 包的 index.js（一个字符串路径），没有 API。

解决：
```bash
unset ELECTRON_RUN_AS_NODE && ./node_modules/.bin/electron .
```
或直接 `npm run dev`（npm scripts 默认不带该变量时正常）。

**② `npm install` 因 `canvas` 原生编译失败**

现象：`Attempting to build a module with a space in the path` → `node-gyp failed to rebuild 'canvas'`。

原因：`pdfjs-dist` 的 optionalDependency `canvas` 需要本地编译，而项目路径含空格。

解决：本项目只做 PDF **文本抽取**，不需要 canvas。
```bash
rm -rf node_modules/canvas
```
并**不要**在 `package.json` 加 `postinstall: electron-builder install-app-deps`（会再次触发编译）。

**③ 打包卡在 winCodeSign 解压：`Cannot create symbolic link`**

现象：
```
ERROR: Cannot create symbolic link : 客户端没有所需的特权 :
...\winCodeSign\...\darwin\10.12\lib\libcrypto.dylib
```

原因：electron-builder 下载的 winCodeSign 包内含 macOS 符号链接，Windows 普通用户无权限创建。

解决：手动解压并排除 darwin 目录（只需一次）：
```bash
CACHE="$LOCALAPPDATA/electron-builder/Cache/winCodeSign"
./node_modules/7zip-bin/win/x64/7za.exe x "$CACHE/729584507.7z" "-o$CACHE/729584507" "-x!darwin" -snld -y
```
之后再 `npm run dist` 会跳过下载。

**④ `release` 目录被占用，无法覆盖**

现象：`remove ...app.asar: The process cannot access the file because it is being used by another process`。

原因：上一次失败的打包或残留 Electron 进程占用文件；且安全删除机制可能拦截 `rm -rf`。

解决：本项目输出目录已改为 `dist-package`（见 `electron-builder.yml`）。若仍被锁，直接用命令行覆盖：
```bash
npx electron-builder --win -c.directories.output=dist-package-$(date +%H%M)
```

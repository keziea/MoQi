# 09 · 构建与发布

## 1. 环境要求

| 项 | 要求 |
|---|---|
| Node.js | ≥ 20（本项目在 22.22.2 验证） |
| npm | ≥ 10 |
| 系统 | Windows 10 / 11 x64 |
| 磁盘 | 约 1.2GB（含 node_modules 与 Electron 二进制） |

## 2. 常用命令

```bash
npm install          # 安装依赖（首次；Electron 二进制较大，耐心等）
npm run dev          # 开发模式（Vite + Electron 热更新）
npm run build        # 编译渲染层与主进程
npm run dist         # 打包 Windows 安装包 → release/
```

## 3. 开发模式原理

```
concurrently
  ├─ vite                 → http://localhost:5173
  └─ wait-on 5173 && tsc -w && electron .
```

`electron/main.ts` 通过 `process.env.VITE_DEV_SERVER_URL` 判断是否加载 dev server。

## 4. 打包配置要点

`electron-builder.yml`：

```yaml
appId: com.moqi.reader
productName: 墨栖
directories:
  output: release
files:
  - dist/**
  - dist-electron/**
  - package.json
win:
  target: nsis
  icon: build/icon.ico
nsis:
  oneClick: false
  allowToChangeInstallationDirectory: true
  createDesktopShortcut: true
  shortcutName: 墨栖
```

**注意事项：**

1. 主进程用 `tsc` 编译到 `dist-electron/`，**不要用 esbuild bundle** —— `pdfjs-dist` 有 worker 文件路径依赖，bundle 后会找不到。
2. `pdfjs-dist` 的 worker 需要在主进程里显式指定：
   ```ts
   import { createRequire } from 'module';
   const require = createRequire(import.meta.url);
   pdfjsLib.GlobalWorkerOptions.workerSrc =
     require.resolve('pdfjs-dist/legacy/build/pdf.worker.mjs');
   ```
3. `asar: true` 时，`pdfjs` 的 cmaps / standard_fonts 需要 `asarUnpack`：
   ```yaml
   asarUnpack:
     - node_modules/pdfjs-dist/**
   ```
4. 应用图标：`build/icon.ico`（256×256，多尺寸）。缺失时用 Electron 默认图标（J4 验收不过）。

## 5. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `Electron failed to install correctly` | 二进制下载失败 | 设 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 后重装 |
| 白屏 | 主进程加载 URL 错误 / preload 路径错 | 检查 `dist-electron/electron/preload.js` 是否存在 |
| `require is not defined` | 主进程被当成 ESM | 主进程 `package.json` 的 `type` 必须为 `commonjs`（或 tsconfig 输出 CJS） |
| PDF 打开报 `worker` 错误 | workerSrc 未指定 | 见 §4.2 |
| 中文书名乱码 | TXT 编码判断错 | 检查 `chardet` 结果，强制 GB18030 兜底 |
| 打包后字体不对 | 系统缺字体 | 字体栈已带 fallback，属正常差异 |
| `dist` 卡在下载 | nsis 资源下载慢 | 设 `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/` |

### 5.1 真实踩过的坑（本项目验证）

**① `npx electron` 以 Node 模式启动，报 `protocol` undefined**

现象：`TypeError: Cannot read properties of undefined (reading 'registerSchemesAsPrivileged')`，堆栈里是 `node:internal/modules`。

原因：环境里存在 `ELECTRON_RUN_AS_NODE=1`，Electron 把自己当 Node 跑，`require('electron')` 返回的是 npm 包的 index.js（一个字符串路径），没有 API。

解决：
```bash
unset ELECTRON_RUN_AS_NODE && ./node_modules/.bin/electron .
```
或直接 `npm run dev`（npm scripts 默认不带该变量时正常）。

**② `npm install` 因 `canvas` 原生编译失败**

现象：`Attempting to build a module with a space in the path` → `node-gyp failed to rebuild 'canvas'`。

原因：`pdfjs-dist` 的 optionalDependency `canvas` 需要本地编译，而项目路径含空格。

解决：本项目只做 PDF **文本抽取**，不需要 canvas。
```bash
rm -rf node_modules/canvas
```
并**不要**在 `package.json` 加 `postinstall: electron-builder install-app-deps`（会再次触发编译）。

**③ 打包卡在 winCodeSign 解压：`Cannot create symbolic link`**

现象：
```
ERROR: Cannot create symbolic link : 客户端没有所需的特权 :
...\winCodeSign\...\darwin\10.12\lib\libcrypto.dylib
```

原因：electron-builder 下载的 winCodeSign 包内含 macOS 符号链接，Windows 普通用户无权限创建。

解决：手动解压并排除 darwin 目录（只需一次）：
```bash
CACHE="$LOCALAPPDATA/electron-builder/Cache/winCodeSign"
./node_modules/7zip-bin/win/x64/7za.exe x "$CACHE/729584507.7z" "-o$CACHE/729584507" "-x!darwin" -snld -y
```
之后再 `npm run dist` 会跳过下载。

**④ `release` 目录被占用，无法覆盖**

现象：`remove ...app.asar: The process cannot access the file because it is being used by another process`。

原因：上一次失败的打包或残留 Electron 进程占用文件；且安全删除机制可能拦截 `rm -rf`。

解决：本项目输出目录已改为 `dist-package`（见 `electron-builder.yml`）。若仍被锁，直接用命令行覆盖：
```bash
npx electron-builder --win -c.directories.output=dist-package-$(date +%H%M)
```

## 2. 强必要 A：安装器同页双路径

### 2.1 结论：NSIS 可以做到同一页

当前 `build/installer.nsh` 已经用 `customPageAfterChangeDir` 插入自定义页，且 `allowToChangeInstallationDirectory: false`，不再依赖自带目录页。把现在的两个 `Page custom` 合成一个即可，**不需要换安装框架**。

### 2.2 页面布局（同一页，上下两组）

```
┌─ 选择安装位置 ─────────────────────────────────────────────┐
│                                                            │
│  ① 程序安装目录                                             │
│     只放 exe、依赖、内置资源，不放书和笔记                    │
│     [ C:\Users\<用户>\AppData\Local\Programs\MoQiReader ] [浏览...] │
│     实际安装到：C:\Users\<用户>\AppData\Local\Programs\MoQiReader   │
│                                                            │
│  ② 用户数据目录                                             │
│     书、笔记、索引、封面、备份、导出包都放这里                │
│     [ C:\Users\<用户>\AppData\Roaming\moqi-reader\data  ] [浏览...] │
│     实际数据：C:\Users\<用户>\AppData\Roaming\moqi-reader\data      │
│                                                            │
│  ⚠ 程序与数据分开存放；卸载默认保留数据，不会误删书和笔记      │
└────────────────────────────────────────────────────────────┘
```

- 两组之间留 8–12u 间距，用 `GroupBox` 或分隔线区分。
- 每组：标题（加粗/深色）+ 一句说明 + 输入框 + 浏览按钮 + 只读预览。
- 页面底部固定一行提示，说明「卸载默认保留数据」。

### 2.3 字段与交互

| 字段 | 控件 | 默认值 | 交互 |
|---|---|---|---|
| 程序安装目录 | `DirRequest` + 浏览 | `%LOCALAPPDATA%\Programs\MoQiReader`（升级时用现有 `$INSTDIR`） | 输入/选择即时刷新「实际安装到」 |
| 用户数据目录 | `DirRequest` + 浏览 | `%APPDATA%\moqi-reader\data`（系统默认） | 选上级后即时刷新「实际数据」 |
| 程序目录预览 | 只读 Label | 拼接后的最终路径 | 已存在 → 黄色提示；受保护 → 红色 + 禁用下一步 |
| 数据目录预览 | 只读 Label | 拼接后的最终路径 | 已有墨栖数据 → 提示「将复用」；已有别的东西 → 红色提示 |

### 2.4 默认值示例

| 场景 | 程序目录默认 | 数据目录默认 |
|---|---|---|
| 全新安装（当前用户） | `%LOCALAPPDATA%\Programs\MoQiReader` | `%APPDATA%\moqi-reader\data` |
| 全新安装（所有用户） | `%ProgramFiles%\MoQiReader`【受保护，会提示换】 | `%APPDATA%\moqi-reader\data` |
| 升级安装 | 注册表里的旧 `$INSTDIR`（只读展示） | 当前指针 → 数据目录（只读展示） |
| 便携版（无安装器） | — | `<exeDir>\MoQiData\data`（见 §7） |

### 2.5 NSIS 实现（稳妥改造）

把现在的两个宏调用：

```nsis
!macro customPageAfterChangeDir
  Page custom MoqiProgramPageCreate MoqiProgramPageLeave
  Page custom MoqiDataPageCreate MoqiDataPageLeave
!macroend
```

改成一个：

```nsis
!macro customPageAfterChangeDir
  Page custom MoqiPathsPageCreate MoqiPathsPageLeave
!macroend
```

页面内用两组控件：

```nsis

    Abort
  ${EndIf}

  ; ── 程序目录 ──
  ${NSD_CreateGroupBox} 0 0 100% 62u "① 程序安装目录（只放程序本体与资源）"
  Pop $0
  ${NSD_CreateDirRequest} 4u 14u 72% 13u "$ProgDir"
  Pop $ProgEdit
  ${NSD_CreateBrowseButton} 77% 14u 21% 13u "浏览..."
  Pop $0
  ${NSD_OnClick} $0 MoqiProgBrowse
  ${NSD_CreateLabel} 4u 30u 92% 26u "实际安装到：$ProgFinal"
  Pop $ProgPreview

  ; ── 数据目录 ──
  ${NSD_CreateGroupBox} 0 66u 100% 62u "② 用户数据目录（书、笔记、索引、备份）"
  Pop $0
  ${NSD_CreateDirRequest} 4u 80u 72% 13u "$DataDir"
  Pop $DataEdit
  ${NSD_CreateBrowseButton} 77% 80u 21% 13u "浏览..."
  Pop $0
```

> 具体坐标需要按 1018 模板实际高度微调；如果两组放不下，缩小说明文字、减少行距，不要拆成两页。

### 2.6 如果同页确实放不下：最贴近的备选

1. **一页 + 折叠**：程序目录默认收起（只显示一行摘要），点「修改」展开；数据目录常显。仍是同一页。
2. **一页两栏**（宽屏）：左侧程序、右侧数据；NSIS 的自定义页宽度有限，不推荐。
3. **两页 + 第二页顶部回显第一页结果**：这是最后备选，不属于「同一页」，需要你确认才用。

### 2.7 风险

- NSIS 自定义页高度固定，两组控件可能拥挤；需要在 100%/125%/150% DPI 下各跑一次。
- 同页后错误提示变多，必须保证「哪一组出错就聚焦哪一组」，不能只弹一个笼统的错误框。
- 升级安装时这一页要变成**只读汇总**（程序 + 现有数据），不能允许改，否则会绕过迁移逻辑。

## 3. 强必要 B：路径追加规则

### 3.1 程序目录：只有盘符根才追加

新规则：

```
用户选 D:\            → D:\MoQiReader
用户选 D:             → D:\MoQiReader
用户选 D:\Apps        → D:\Apps          （不再追加）
用户选 D:\Apps\MoQiReader → 原样使用
```

判断逻辑（NSIS）：

```nsis
StrLen $0 "$ProgRoot"
${If} $0 <= 3            ; "D:" 或 "D:\"
  StrCpy $INSTDIR "$ProgRoot\${PROGRAM_DIR_NAME}"
${Else}
  StrCpy $INSTDIR "$ProgRoot"
${EndIf}
```

同时：

- 如果 `D:\Apps` 里已经有文件/子文件夹，显示黄色提示：
  `这个文件夹不是空的，程序文件会直接放在这里，不会另建 MoQiReader。建议选空文件夹或盘符根。`
- 受保护目录（Program Files / Windows / 系统盘根）继续拦截。
- 升级安装跳过此页，沿用旧 `$INSTDIR`，不做任何追加。

### 3.2 数据目录：固定层始终追加（除非已经是该名）

数据目录的语义是「你选一个**上级**，我在里面建固定名」：

```
用户选 E:\            → E:\MoQiData
用户选 E:\Backups     → E:\Backups\MoQiData
用户选 E:\MoQiData    → E:\MoQiData     （已经是固定名，不再套）
```

判断逻辑：

```nsis
StrCpy $0 "$DataParent"
; 去尾斜杠
StrCpy $1 "${DATA_DIR_NAME}"
${GetFileName} $2 "$0"
${If} $2 == "$1"
  StrCpy $DataRoot "$0"
${Else}
  StrCpy $DataRoot "$0\$1"
${EndIf}
```

### 3.3 示例总表

| 用户选择 | 程序目录结果 | 数据目录结果 |
|---|---|---|
| `D:\` | `D:\MoQiReader` | — |
| `D:\Apps` | `D:\Apps`（提示非空） | — |
| `D:\Apps\MoQiReader` | `D:\Apps\MoQiReader` | — |
| `E:\` | — | `E:\MoQiData` |
| `E:\Backups` | — | `E:\Backups\MoQiData` |
| `E:\MoQiData` | — | `E:\MoQiData` |
| `C:\Program Files` | 拦截 | 拦截 |

### 3.4 迁移方案与风险

- **老用户升级**：程序页跳过，继续用 `...\moqi-reader`；不强制改成 `MoQiReader`，不会多装一份。
- **新用户**：程序目录按新规则；数据目录如果留在系统默认，仍是 `%APPDATA%\moqi-reader\data`，不动。
- **风险**：用户选 `D:\Apps` 直接装，程序文件会和别的软件混在一起。必须给非空提示，并建议「在下面新建 MoQiReader」的快捷按钮（点了就变成 `D:\Apps\MoQiReader`，但不强制）。
- **不建议**在用户选了具体文件夹后偷偷再套一层：这正是本次要修掉的行为。

## 4. 强必要 C：设置内改数据目录

### 4.1 现状

- 入口：工作台「数据备份与恢复 → 数据位置」、阅读页「阅读设置 → 数据 → 数据存放位置」。
- 流程：选上级 → 确认框「复制 / 移动 / 取消」→ 复制 → 校验 → 写指针 → 自动重启。
- 已有：失败回滚、旧位置延迟清理、路径改写、外部书收编。
- 缺：迁移前**可感知的**备份、目标已存在的三选项。

### 4.2 目标流程

```
1. 展示当前数据目录（完整路径）
2. 点「浏览选择新位置」→ 选一个上级目录
3. 计算 <上级>\MoQiData；若末级已是 MoQiData，原样使用
4. 检查目标：
   ├─ 不存在          → 继续
   ├─ 已有墨栖数据    → 弹四选一：复用 / 覆盖 / 重命名 / 取消
   └─ 已有别的东西    → 只给：重命名 / 取消
5. 选复制或移动：
   ├─ 复制：旧目录原样保留（即备份）
   └─ 移动：先写备份清单，旧目录保留 7 天；7 天内可「立即清理」
6. 复制 → 校验文件数/关键 JSON → 改写书路径 → 写指针
7. 提示「重启生效」→ 自动重启
8. 失败：删本次产物，指针不动，原数据可读
```

### 4.3 目标已存在的三种处理

| 选择 | 行为 | 数据风险 |
|---|---|---|
| **复用** | 不复制，直接把指针指过去；当前数据保留在原处 | 目标数据成为当前数据；原数据仍在，可回退 |
| **覆盖** | 先把目标目录整体改名成 `MoQiData-backup-<时间戳>`，再迁移 | 目标旧数据不删除，改名保留；失败可改回 |
| **重命名** | 目标改成 `MoQiData-2` / `MoQiData-<日期>`，再迁移 | 无 |
| **取消** | 什么都不做 | 无 |

> 不做「直接清空目标」的覆盖。覆盖 = 先改名备份，再写入，确保可回滚。

### 4.5 迁移前备份（针对「移动」）

现状：复制 → 校验 → 写指针 → 下次启动删旧。
问题：如果新位置其实不可用（权限、盘符、杀毒拦截），下次启动删旧就晚了。

建议：

- `pending-cleanup.json` 增加 `deleteAfter` 字段（默认 7 天后）；
- 启动清理只在 `now > deleteAfter` 且新数据能正常读出 `library.json` 时执行；
- 设置页显示「旧数据将在 X 天后清理」+「立即清理」按钮；
- 复制模式不写清理指令，旧目录永久保留，直到用户手动删。

> 这是「自动备份」的落地方式：旧目录本身就是备份，不额外做 ZIP，避免大书库双倍占用。
> 如果坚持要独立快照，可加 `_backups/migration-<时间戳>.zip`（仅移动模式、可选、默认关）。

### 4.6 风险

- 复用目标数据后，当前数据还在原处，用户可能以为是「合并」；文案必须写明「不会合并，只是切换」。
- 覆盖 = 改名备份，会额外占用一份目标旧数据；磁盘不足时要先检查。
- 7 天保留期会让磁盘多占一份；需要在设置里明确提示和「立即清理」。

---

## 5. 强必要 D：命名规范

### 5.1 决策矩阵

| 方案 | 示例 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| `MoQiData`（当前） | `E:\MoQiData` | 含 Data、无缩写、应用可辨识、避免和别的软件 `data` 冲突 | 内部还有一层 `data`，两层重复 | **推荐** |
| `data`（纯标准词） | `E:\data` | 最标准、最短 | 盘符根下极易冲突；多个软件共用一个 `data` 时分不清 | 不推荐做自定义根 |
| `moqi-data`（kebab） | `E:\moqi-data` | 和包名 `moqi-reader` 一致 | 和程序目录 `MoQiReader` 风格不统一 | 备选（若程序也改 kebab） |
| `MoQiReaderData` | `E:\MoQiReaderData` | 最明确 | 太长 | 备选 |

**推荐**：程序 `MoQiReader`，数据 `MoQiData`，两者都是 PascalCase、都含完整单词，全项目统一。
`data` 作为**内层**目录名（当前 `MoQiData\data`）是标准词，指向用户数据，不混程序资源。

### 5.2 关于「两层 data」的处理

当前：

```
E:\MoQiData\data\library.json
E:\MoQiData\data\books\...
```

问题：`MoQiData\data` 重复。

两个选项：

| 选项 | 结构 | 改造量 | 风险 | 分类 |
|---|---|---|---|---|
| A. 保留现状 | `MoQiData\data\...` | 0 | 无 | 默认 |
| B. 扁平化 | `MoQiData\library.json`、`MoQiData\books\...` | 中：`paths.ts` 全部路径、迁移脚本、测试 | 需要一次性迁移，旧备份包结构要兼容 | 可选（建议 v0.6） |

如果选 B，迁移方式：

1. 启动检测 `MoQiData\data\library.json` 存在且 `MoQiData\library.json` 不存在；
2. 把 `data\*` 移到 `MoQiData\`（同盘 rename，跨盘复制+校验）；
3. 写 `.layout-version=2`；
4. 失败回滚到 `data\`；
5. 备份包 manifest 增加 `layoutVersion`，恢复时按版本落位。

> 不建议这轮做扁平化：它会同时动安装器、运行时路径、备份包、迁移逻辑，属于激进重构。
> 命名本身已经满足「见名知意」，重复层是结构问题，不是命名问题。

### 5.3 旧命名兼容

- 数据指针 `data-root.txt` 存的是**绝对路径**，不依赖目录名；旧 `MoQiReader` 目录继续可用。
- 新位置才创建 `MoQiData`；不强制重命名旧目录。
- 程序目录旧 `moqi-reader` 只影响升级用户；新装用户用 `MoQiReader`，两套并存不冲突。
- 备份包 `manifest.json` 里的 `app` 字段改成 `APP_NAME_EN` 变量，不写死。

## 7. 解压版（便携包）专项

现状：`portable.flag` 判据；默认 `<exeDir>\MoQiData\data`；用户可在设置改到外部；指针写在 exe 同级。
与本次要求的差距：

1. 默认数据目录是 `MoQiData\data`，不是「程序根下一个 `data`」。
2. 如果改成 `<exeDir>\data`，与安装版的 `MoQiData\data` 又不一致。

建议二选一：

| 方案 | 便携默认 | 安装版自定义 | 一致性 | 风险 |
|---|---|---|---|---|
| A（推荐） | `<exeDir>\MoQiData\data` | `<上级>\MoQiData\data` | 完全一致 | 多一层目录，但名字清楚 |
| B（更贴字面） | `<exeDir>\data` | `<上级>\MoQiData\data` | 不一致 | 用户会问为什么两边不一样 |

如果坚持「解压后程序根下就是 `data`」，选 B，但要在设置页写明「便携版默认 `<exeDir>\data`，安装版默认 `%APPDATA%\moqi-reader\data`；自定义时统一用 `MoQiData`」。我个人建议 A，保持一套规则。

## 8. 改造清单：稳妥 vs 激进

### 8.1 稳妥改造（建议本轮 v0.5.2）

1. `build/installer.nsh`
   - 两个 `Page custom` 合并成一个 `MoqiPathsPage`；
   - 程序目录判断改成「只有盘符根才追加」；
   - 非空文件夹黄色提示；
   - 升级时整页只读汇总。
2. `electron/store/location.ts`
   - `LocationPlan` 增加 `existing: 'none' | 'moqi' | 'other'`；
   - `relocateData` 增加 `existingAction`；
   - `pending-cleanup` 增加 `deleteAfter`（7 天）；
   - 覆盖 = 目标改名备份。
3. `electron/ipc/index.ts`
   - 目标已存在的四选一/两选一对话框；
   - 迁移完成提示保留期。
4. `SettingsPanel` / `DataBackup`
   - 显示「旧数据将在 X 天后清理」+「立即清理」；
   - 文案区分复用/覆盖/重命名。
5. 测试
   - 同页安装器：全新安装、升级、非空文件夹、盘符根、受保护目录；
   - 设置：复用、覆盖、重命名、取消、移动保留期、失败回滚。
6. 文档/发布说明同步。

### 8.2 激进重构（不建议本轮）

1. 数据布局扁平化（`MoQiData\data` → `MoQiData\`）：
   - 动 `paths.ts` 所有路径、备份 manifest、恢复逻辑、测试；
   - 需要一次性迁移和回滚；
   - 建议单独 v0.6.0，不和安装器改造混在一起。
2. 把默认数据目录从 `%APPDATA%\moqi-reader\data` 改到 `%APPDATA%\MoQiData`：
   - 老用户数据会「消失」（还在旧路径）；
   - 需要启动时自动迁移或提示；
   - 风险高，收益低。
3. 安装器改成 Inno Setup / WiX：
   - 现有 NSIS 已能实现同页双路径；
   - 换框架会重做签名、卸载、升级、快捷方式，不建议。

## 9. 迁移与风险总表

| 变更 | 老用户影响 | 迁移方式 | 风险 |
|---|---|---|---|
| 安装器同页 | 升级只读汇总，不改变路径 | 无需迁移 | 页面拥挤/DPI |
| 程序目录追加规则 | 升级沿用旧 `$INSTDIR` | 无需迁移 | 新用户选 `D:\Apps` 会混放，需提示 |
| 目标同名三选项 | 只在用户主动改位置时出现 | 复用/改名/覆盖备份 | 覆盖占双份空间 |
| 移动保留 7 天 | 旧目录多留 7 天 | `deleteAfter` | 磁盘占用 |
| 数据名 `MoQiData` | 旧指针仍指 `MoQiReader` | 不强制改名 | 两套名字并存 |
| 扁平化（可选） | 需要迁移 | rename/copy + 校验 | 备份包兼容 |
| 便携默认 | 老用户 AppData 数据先沿用 | `legacyPortable` | 新老规则不一致 |

# 10 · 安装包与数据目录设计（Windows 优先）

> 面向：安装器、便携包、运行时路径服务、数据迁移、卸载。
> 现状基线：Electron 33 + electron-builder 25 + NSIS 3（assisted installer）。
> 本文所有名称都用占位符，替换点集中在 `package.json → moqi` 与 `scripts/gen-names.js`，**不允许在安装脚本或业务代码里硬编码**。

---

## 1. 方案总览

### 1.1 三层结构

```
┌─────────────────────────────────────────────────────────────┐
│ ① 名字常量层（构建时生成，唯一真相）                          │
│    package.json → moqi.{appNameEn, programDir, dataDir}      │
│    scripts/gen-names.js                                      │
│      ├─ build/folder-names.nsh   → 安装器 !define             │
│      └─ shared/names.generated.ts → 主进程 / 渲染层 import     │
└─────────────────────────────────────────────────────────────┘
              │                              │
┌─────────────▼──────────────┐   ┌───────────▼─────────────────┐
│ ② 安装器（NSIS / Inno）     │   │ ③ 运行时路径服务             │
│  · 程序目录：选根 → 拼固定名 │   │  · 读指针 → 解析 dataRoot    │
│  · 数据目录：默认 / 自定义   │   │  · 便携模式判定              │
│  · 已存在：复用 / 换 / 取消  │   │  · 迁移（复制/移动）+ 回滚   │
│  · 受保护目录拦截            │   │  · 卸载时只删程序，不删数据  │
└──────────────────────────────┘   └─────────────────────────────┘
```

### 1.2 四条硬约束

1. **数据可独立迁移**：数据根目录只由「用户选的上级目录 + 固定数据目录名」决定，和程序装在哪无关。
2. **固定层不可改名**：用户只能选上级目录，`{{DATA_DIR}}` 这一层由程序拼接，不提供输入框。
3. **程序目录纯程序**：exe、dll、resources 之外不写任何东西；配置、缓存、日志、备份、书全部在数据目录。
4. **卸载默认不删数据**：删除数据必须是显式勾选 + 二次确认，且只删数据根，不碰程序目录。

| 能力 | 状态 | 位置 |

## 2. 目录约定（含占位符）

### 2.1 占位符与替换点

| 占位符 | 含义 | 当前绑定 | 替换点 |
|---|---|---|---|
| `{{APP_NAME}}` | 中文产品名（快捷方式、窗口标题） | 墨栖 | `electron-builder.yml → productName` |
| `{{APP_NAME_EN}}` | 英文包名 / 配置目录名 | `moqi-reader` | `package.json → name` |
| `{{APP_ID}}` | 反向域名 ID | `com.moqi.reader` | `electron-builder.yml → appId` |
| `{{PROGRAM_DIR}}` | 程序安装目录的固定末级名 | `moqi-reader` | `package.json → moqi.programDir` |
| `{{DATA_DIR}}` | 数据根目录的固定名（用户不可改） | `MoQiData` | `package.json → moqi.dataDir` |
| `{{PUBLISHER}}` | 发布者（签名、公司名） | Moqi | `electron-builder.yml → copyright/companyName` |

`package.json` 增加一段（只此一处）：

```json
{
  "moqi": {
    "appNameEn": "moqi-reader",
    "programDir": "moqi-reader",
    "dataDir": "MoQiData"
  }
}
```

`scripts/gen-names.js`（构建前运行，生成两个文件）：

```js
const fs = require('node:fs');
const path = require('node:path');
const pkg = require('../package.json');

const n = pkg.moqi || {};
const appNameEn = n.appNameEn || pkg.name;
const programDir = n.programDir || pkg.name;
const dataDir = n.dataDir || 'AppData';

const nsh = `; 由 scripts/gen-names.js 生成，不要手改
!define APP_NAME_EN "${appNameEn}"
!define PROGRAM_DIR_NAME "${programDir}"
!define DATA_DIR_NAME "${dataDir}"
`;
fs.writeFileSync(path.join(__dirname, '..', 'build', 'folder-names.nsh'), nsh, 'utf8');

const ts = `// 由 scripts/gen-names.js 生成，不要手改
export const APP_NAME_EN = '${appNameEn}';
export const PROGRAM_DIR_NAME = '${programDir}';
export const DATA_DIR_NAME = '${dataDir}';
`;
fs.writeFileSync(path.join(__dirname, '..', 'shared', 'names.generated.ts'), ts, 'utf8');
```

`package.json → scripts.build` 首行插入 `node scripts/gen-names.js &&`。
NSIS 侧 `!include "folder-names.nsh"`，业务侧 `import { DATA_DIR_NAME } from '@shared/names.generated'`。

### 2.2 Windows · 安装版

```
<用户选的根>\{{PROGRAM_DIR}}\                  ← 程序目录，只读用途
├── {{APP_NAME}}.exe
├── resources\app\...
├── locales\
└── ...

%APPDATA%\%{{APP_NAME_EN}}\                    ← 指针与日志（极小）
├── data-root.txt                              ← 一行绝对路径 = 数据根
└── logs\main.log

<数据根>\                                      ← 默认 %APPDATA%\%{{APP_NAME_EN}}；也可 D:\xxx\{{DATA_DIR}}
└── data\
    ├── .moqi-data                             ← {"app","kind","version"}
    ├── library.json                           ← 书架、分类、封面名、多格式
    ├── settings.json                          ← 阅读设置、笔记分类
    ├── user\
    │   ├── progress.json
    │   ├── notes.json
    │   └── sessions.json
    ├── books\{bookId}\
    │   ├── cover.jpg
    │   ├── book.json                          ← 解析缓存（可重建）
    │   ├── assets\                            ← EPUB 内图片
    │   └── source\                            ← 原书文件（自包含关键）
    ├── _backups\{yyyyMMdd-HHmm}\              ← 导入前安全垫
    ├── pending-cleanup.json                   ← 迁移后待删旧目录
    └── migrating.lock                         ← 迁移互斥（存在即上次未完成）
```

> 默认数据根 = `app.getPath('userData')`（Electron 自动映射到 `%APPDATA%\%{{APP_NAME_EN}}`），其下再放 `data/`，避免指针文件和数据混在同一层。

### 2.3 Windows · 便携包

```
<解压目录>\                                     ← 程序同级，可整个拷走
├── {{APP_NAME}}.exe
├── resources\...
├── portable.flag                              ← {"app","version","mode":"portable"}
├── data-root.txt                              ← 仅当用户改过外部位置才存在
└── {{DATA_DIR}}\                              ← 默认数据根（程序同级固定目录）
    └── data\...
```

便携包规则：

1. 有 `portable.flag` 且 `data-root.txt` 不存在 → 数据根 = `<exeDir>\{{DATA_DIR}}`。
2. `<exeDir>` 不可写（只读 U 盘 / 光盘）→ 回退 `%APPDATA%\%{{APP_NAME_EN}}`，并在设置页黄条提示「当前使用系统目录」。
3. 用户在设置里改到外部 → 指针写到 **`<exeDir>\data-root.txt`**（不是 AppData），保证整个便携目录拷到别的电脑仍然指向正确位置；`<exeDir>` 不可写时退回 AppData 指针并提示。
4. 便携包不写注册表、不建开始菜单项、不注册卸载器。

### 2.4 数据目录内部子目录创建时机

| 子目录 | 创建时机 | 缺失时行为 |
|---|---|---|
| `data\` | 首次启动 / 迁移落位 | 自动 `mkdir -p` |
| `data\user\` | `ensureDirs()` | 自动创建，读不到按空对象 |
| `data\books\` | 同上 | 同上 |
| `data\books\{id}\source\` | 导入 / 恢复 / 收编外部书 | 自动创建 |
| `data\_backups\` | 每次导入前 | 自动创建 |
| `data\logs\` | 建议把主进程日志也放数据侧 | 自动创建；写不了退回 AppData |

### 2.5 macOS / Linux 默认路径（预留）

| 平台 | 程序 | 数据根 | 缓存/日志 |
|---|---|---|---|
| Windows | `%LOCALAPPDATA%\Programs\{{PROGRAM_DIR}}` 或用户选 | `%APPDATA%\%{{APP_NAME_EN}}` | `%LOCALAPPDATA%\%{{APP_NAME_EN}}\cache` |
| macOS | `/Applications/{{APP_NAME}}.app` | `~/Library/Application Support/{{APP_NAME_EN}}` | `~/Library/Caches/{{APP_NAME_EN}}`、`~/Library/Logs/{{APP_NAME_EN}}` |
| Linux | `/opt/{{PROGRAM_DIR}}` 或 AppImage 同级 | `$XDG_DATA_HOME/{{APP_NAME_EN}}`（缺省 `~/.local/share`） | `$XDG_CACHE_HOME/{{APP_NAME_EN}}`、`$XDG_STATE_HOME/{{APP_NAME_EN}}` |

Electron 的 `app.getPath('userData')` 已按上表映射；迁移逻辑只认「数据根 + `data/`」，不依赖平台。

### 2.6 路径规则

- 只接受绝对路径；相对路径、空串、只含空白 → 拒绝。
- 末尾 `\` 统一去掉（盘符根 `E:\` 保留为 `E:` 再拼）。
- 路径总长 ≤ 240 字符（给 `\books\{id}\source\长文件名` 留余量）。
- 禁止 `..` 段、禁止把数据根设到程序目录内部。
- 中文/空格允许；`CON`、`PRN`、`AUX`、`NUL`、`COM1..9`、`LPT1..9` 作为末级名时拒绝（Windows 保留名）。

## 3. 安装向导流程与 UI

### 3.1 页面顺序

```
① 欢迎
② 安装模式（仅当前用户 / 所有用户）        ← electron-builder 自带
③ 程序位置（自定义页，实时预览）
④ 数据位置（自定义页，默认/自定义）
⑤ 确认汇总（程序目录 + 数据目录 + 是否已有数据）
⑥ 安装中
⑦ 完成（启动勾选）
```

> 若要严格做到「程序位置实时预览」，必须 **关闭 electron-builder 自带的目录页**（`allowToChangeInstallationDirectory: false`），用 ③ 取代它；否则自带页只在离开后才由 `instFilesPre` 拼接末级目录，页面上看不到最终路径。当前 0.5.0 采用折中：自带页 + ④ 顶部显示最终程序目录。

### 3.2 程序位置页（③）

| 字段 | 控件 | 说明 |
|---|---|---|
| 安装根目录 | `DirRequest` + `浏览...` | 默认 `%LOCALAPPDATA%\Programs`；用户选 `D:\` 就显示 `D:\` |
| 最终目录 | 只读标签，实时刷新 | `根 + "\" + {{PROGRAM_DIR}}`；若根末级已是 `{{PROGRAM_DIR}}`，不再重复拼 |
| 已存在提示 | 黄色标签 | `该目录已存在，安装会覆盖程序文件，但不会动用户数据` |
| 受保护提示 | 红色标签 + 禁用下一步 | 命中 §3.5 列表时 |

交互文案：

- 标签：`程序会安装到：D:\{{PROGRAM_DIR}}`
- 已存在：`这个位置已经有 ${PRODUCT_NAME}，继续安装会更新程序文件；书和笔记在数据目录里，不受影响。`
- 空/非法：`请选择一个完整的文件夹路径。`
- 无权限：`这个位置当前账户写不进去，请换一个目录，或以管理员身份运行。`

### 3.3 数据位置页（④）

两种模式，用单选切换：

```
( ) 使用系统默认位置
    C:\Users\<用户>\AppData\Roaming\{{APP_NAME_EN}}\data
( ) 放到我自己选的位置
    上级目录：[ E:\                ] [浏览...]
    将创建：  E:\{{DATA_DIR}}
    数据目录：E:\{{DATA_DIR}}\data
```

规则：

- 默认选中「系统默认位置」，不创建任何目录，指针文件也不写（应用启动时按默认值走）。
- 选「自定义」后，只让用户选**上级目录**；`{{DATA_DIR}}` 由程序拼接，只读展示。
- 上级目录不存在 → 红字 `这个文件夹不存在，请重新选择。`
- 目标 `<上级>\{{DATA_DIR}}` 已存在 → 弹三选一：
  1. **复用**（该目录已有 `data\library.json` 或 `.moqi-data`）→ 直接指向它，不覆盖；
  2. **换一个位置** → 返回选择；
  3. **取消安装**。
- 目标存在但不是墨栖数据（没有标记/没有 `library.json`）→ 只允许「换位置 / 取消」，不允许复用，避免误伤别的软件。
- 受保护目录 → 阻断（见 §3.5）。
- 页面底部固定一行：`这一层文件夹名 {{DATA_DIR}} 由 {{APP_NAME}} 固定使用，不能改名；你只需要选它放在哪个上级目录。`

### 3.4 已存在目录的判定与策略

| 情况 | 判定 | 行为 |
|---|---|---|
| 目标不存在 | `not exists` | 创建，继续 |
| 存在且含 `.moqi-data` | 墨栖数据 | 复用；页面提示「将使用已有数据，不会覆盖」 |
| 存在且含 `data\library.json` | 墨栖数据（旧版无标记） | 复用；启动时补写标记 |
| 存在但为空 | 空目录 | 视为可复用（无数据可丢） |
| 存在且有其他文件 | 非墨栖目录 | 拒绝复用，只允许换位置/取消 |
| 目标就是当前数据根 | 同路径 | 提示「数据已经在这里」，不重复迁移 |

### 3.5 受保护目录清单（安装与数据都适用）

以下路径（含子目录）一律拦截，提示换位置：

- `%ProgramFiles%`、`%ProgramFiles(x86)%`、`%SystemRoot%`、`%SystemDrive%\`（根目录）
- `%ProgramData%` 根（允许 `%ProgramData%\<厂商>\<应用>` 但需管理员，普通安装不推荐）
- 任何 `C:\Windows\*`、`C:\Program Files*`
- 网络盘 / OneDrive 同步根（警告但允许，见 §9）

拦截文案：

> `{{APP_NAME}} 不把数据放在系统受保护目录里：这类目录需要管理员权限，程序读写会被 Windows 虚拟化重定向，导致“文件明明在却读不到”。请换到 D:\、文档或用户目录下。`

### 3.6 升级安装

- 程序位置页跳过（沿用注册表里的旧 `$INSTDIR`），只显示汇总。
- 数据位置页 **只读展示**：`现有数据位置：<指针或默认>`，并提示：

  > `安装不会移动数据。要换位置，装好后在「阅读设置 → 数据 → 数据存放位置」里改，墨栖会自动搬过去。`

- 不在安装器里迁移数据：安装器没有应用层的校验/回滚能力，搬几十 GB 书库风险不可控。

### 3.7 异常提示总表

| 场景 | 文案 | 是否阻断 |
|---|---|---|
| 路径为空 | 请选择一个文件夹。 | 是 |
| 路径含非法字符 | 路径里有 Windows 不允许的字符（`<>:"|?*`）。 | 是 |
| 路径过长（>240） | 这个路径太长了，请换一个更浅的目录。 | 是 |
| 盘符不存在 | 找不到这个磁盘，请确认移动硬盘已插好。 | 是 |
| 无写权限 | 这个位置当前账户写不进去，请换目录或使用管理员安装。 | 是 |
| 空间不足（安装前检查） | 这个磁盘剩余空间不足，至少需要 xxx MB。 | 是 |
| 目标已存在且非墨栖数据 | 这个文件夹里已经有别的内容，为避免误覆盖，请换一个位置。 | 是 |
| 数据目录不可写（启动时） | 数据位置打不开，已临时使用默认位置。 | 否，回退 |

## 4. 安装包：配置与脚本实现

### 4.1 electron-builder.yml（关键段）

```yaml
appId: com.moqi.reader
productName: 墨栖
directories:
  output: out-app
  buildResources: build

win:
  icon: build/icon.ico
  signAndEditExecutable: false   # 由 scripts/after-pack.js 写 rcedit

nsis:
  oneClick: false
  # 目标设计：关闭自带目录页，用自定义页实现实时预览（见 §4.3）
  # 当前 0.5.0 仍是 true（自带页 + 下一页显示最终路径），切换前需重新跑安装测试
  allowToChangeInstallationDirectory: false
  perMachine: false
  allowElevation: true
  include: installer.nsh
  artifactName: Moqi-${version}-Setup.${ext}
  deleteAppDataOnUninstall: false
```

### 4.2 名字注入

- `scripts/gen-names.js` 生成 `build/folder-names.nsh`（§2.1）。
- `build/installer.nsh` 第一行 `!include "folder-names.nsh"`。
- 所有目录拼接使用 `${PROGRAM_DIR_NAME}` / `${DATA_DIR_NAME}`，**禁止**出现 `moqi-reader`、`MoQiData` 字面量。

### 4.3 NSIS：程序页 + 数据页（可编译骨架）

> 前提：`allowToChangeInstallationDirectory: false`，由下面的 `MoqiProgramPage` 接管程序目录。

```nsis
!include "MUI2.nsh"
!include "nsDialogs.nsh"
!include "LogicLib.nsh"
!include "FileFunc.nsh"
!include "folder-names.nsh"

Var ProgPage
Var ProgRootEdit
Var ProgPreview
Var ProgWarn
Var DataPage
Var DataModeDefault
Var DataModeCustom
Var DataParentEdit
Var DataPreview
Var DataWarn

!macro customPageAfterChangeDir
  Page custom MoqiProgramPageCreate MoqiProgramPageLeave
  Page custom MoqiDataPageCreate MoqiDataPageLeave
!macroend

; ── 程序位置 ──────────────────────────────────────────────
Function MoqiProgramPageCreate
  ; 升级：直接跳过，沿用 $INSTDIR
  ${If} ${isUpdated}
    Abort
  ${EndIf}

  !insertmacro MUI_HEADER_TEXT "选择程序安装位置" "程序文件只放在这里，用户数据放在下一页。"

  nsDialogs::Create 1018
  Pop $ProgPage
  ${If} $ProgPage == error
    Abort
  ${EndIf}

  ${NSD_CreateLabel} 0 0 100% 20u "选一个根目录，${PRODUCT_NAME} 会在里面创建固定的 ${PROGRAM_DIR_NAME} 文件夹。"
  Pop $0

  ${NSD_CreateDirRequest} 0 24u 78% 13u "$LOCALAPPDATA\Programs"
  Pop $ProgRootEdit
  ${NSD_OnChange} $ProgRootEdit MoqiProgRefresh

  ${NSD_CreateBrowseButton} 79% 24u 21% 13u "浏览..."
  Pop $0
  ${NSD_OnClick} $0 MoqiProgBrowse

  ${NSD_CreateLabel} 0 44u 100% 30u ""
  Pop $ProgPreview

  ${NSD_CreateLabel} 0 74u 100% 26u ""
  Pop $ProgWarn

  Call MoqiProgRefresh
  nsDialogs::Show
FunctionEnd

Function MoqiProgRefresh
  ${NSD_GetText} $ProgRootEdit $0
  ${If} $0 == ""
    ${NSD_SetText} $ProgPreview "请选择一个安装位置。"
    ${NSD_SetText} $ProgWarn ""
    Return
  ${EndIf}
```

## 5. 便携解压包

### 5.1 打包

`scripts/pack.js` 在复制完成后：

```js
fs.writeFileSync(
  path.join(FINAL_DIR, 'portable.flag'),
  JSON.stringify({ app: APP_NAME_EN, version: VERSION, mode: 'portable' }, null, 2),
  'utf8'
);
```

目录结构见 §2.3。`portable.flag` 是便携模式的唯一判据（安装版没有这个文件）。

### 5.2 启动时的数据根解析（优先级）

```ts
function resolveDataRoot(): DataRootInfo {
  const portable = exists(join(exeDir, 'portable.flag'));

  // 1. 便携目录里的指针优先
  if (portable) {
    const local = readPointer(join(exeDir, 'data-root.txt'));
    if (local && usable(local)) return custom(local);
  }

  // 2. 系统指针（安装版 / 便携版改到外部后回退）
  const sys = readPointer(join(app.getPath('userData'), 'data-root.txt'));
  if (sys && usable(sys)) return custom(sys);

  // 3. 便携默认：程序同级固定目录
  if (portable) {
    const fallback = join(exeDir, DATA_DIR_NAME);
    if (canWrite(exeDir)) return custom(fallback);
    // 只读介质：退回系统目录并记录原因
    return { ...systemDefault(), portableReadonly: true };
  }

  // 4. 安装版默认
  return systemDefault();
}
```

`canWrite(dir)`：创建 `.moqi-write-test` 再删除，或 `fs.accessSync(dir, W_OK)`（Windows 上 access 不可靠，用创建测试）。

### 5.3 便携版改到外部

- 指针写到 `<exeDir>\data-root.txt`（可写时）；不可写则写 AppData 并提示「便携目录只读，位置记录在系统里，换电脑后需要重新设置」。
- 迁移逻辑与安装版共用 `relocateData()`。
- 整个便携目录拷到另一台电脑：指针是相对/绝对？**必须存绝对路径**；若目标盘符变化，指针失效 → 启动回退到 `<exeDir>\{{DATA_DIR}}` 并提示「原来的外部数据位置找不到」。

### 5.4 便携版不写系统

- 不写注册表、不建快捷方式、不注册卸载器。
- 日志、缓存全部在数据目录；程序目录只多一个 `portable.flag`（打包时写入，运行时不改）。

## 6. 设置页切换数据目录

### 6.1 位置

- 工作台 →「数据备份与恢复」→「数据位置」（主入口）
- 阅读页 →「阅读设置」→「数据」→「数据存放位置」（阅读中也能改）

### 6.2 UI 字段

```
数据存放位置
C:\Users\<用户>\AppData\Roaming\moqi-reader\data
[ 更改位置 ]  [ 改回默认 ]

○ 复制到新位置（推荐，旧数据保留）
○ 移动到新位置（完成后删除旧目录）

[迁移] 迁移中：123 / 456 个文件 · 已复制 1.2 GB
```

### 6.3 交互流程

1. 点「更改位置」→ `showOpenDialog({ properties: ['openDirectory','createDirectory'] })`。
2. 计算 `plan = <parent>\{{DATA_DIR}}`；若父目录末级已是 `{{DATA_DIR}}`，直接用。
3. 前端/主进程校验：空、非法、过长、盘不存在、受保护、在当前数据目录内部、目标已有墨栖数据。
4. 弹确认框，写明：
   - 将创建：`E:\{{DATA_DIR}}`
   - 数据目录：`E:\{{DATA_DIR}}\data`
   - 当前数据量：`12 本书 / 340 条笔记 / 1.2 GB`
   - 模式：复制 / 移动
5. 执行迁移（§7），进度事件 `location:progress`。
6. 成功 → 写指针 → 提示「重启生效」→ 1.4s 后 `app.relaunch()`。
7. 失败 → 原数据不动，新位置半成品删除，显示错误。

### 6.4 复制 vs 移动

| 模式 | 行为 | 磁盘 | 适用 |
|---|---|---|---|
| 复制 | 复制 → 校验 → 写指针 → **保留旧数据**，提示旧路径可自行删除 | 双份 | 换盘、先验证再删（默认） |
| 移动 | 复制 → 校验 → 写指针 → 写 `pending-cleanup.json` → 下次启动删旧 | 单份 | 确定不要旧位置 |

> 不做原地 `rename`：跨盘会失败，且中途崩溃会留下半套数据。

### 6.5 配置读写

`%APPDATA%\%{{APP_NAME_EN}}\data-root.txt`（安装版）或 `<exeDir>\data-root.txt`（便携版）：

```
E:\MoQiData
```

- UTF-8 无 BOM；一行；无末尾换行。
- 读：`trim()` + `path.resolve()`；空文件视为无指针。
- 写：先写 `.tmp` 再 `rename`，避免半截文件。
- 删除 = 回到默认。

字段说明：

| 文件 | 字段 | 类型 | 说明 |
|---|---|---|---|
| `data-root.txt` | 第一行 | string | 数据根绝对路径（不含 `\data`） |
| `data\.moqi-data` | `app` / `kind` / `version` | string | 识别墨栖数据，防误删/误覆盖 |
| `data\pending-cleanup.json` | `old` / `at` | string / number | 下次启动删除的旧目录 |
| `data\migrating.lock` | `pid` / `at` / `target` / `mode` | number/string | 迁移互斥；启动发现即视为上次中断，走恢复流程 |
| `portable.flag` | `app` / `version` / `mode` | string | 便携模式判据 |

## 7. 迁移与回滚

### 7.1 状态机

```
idle
  → planning        校验目标、检查冲突
  → copying         复制到 <target>\.moqi-data-tmp-<ts>
  → verifying       比对文件数 / 总字节 / 关键 JSON 可解析
  → rewriting       改写 library.json 路径 + 收编外部书
  → committing      改名 tmp → data；写指针
  → done            重启
  ↘ failed          清理 tmp / 回滚指针
```

### 7.2 核心步骤（伪代码）

```ts
async function relocate(target, mode /* 'copy' | 'move' */, onProgress) {
  const oldData = paths.data();
  const { root, dataDir } = plan(target);
  if (isInside(root, oldData) || same(root, currentRoot)) throw new Error('目标非法');
  if (exists(dataDir)) throw new Error('目标已有数据');

  const tmp = join(root, `.moqi-data-tmp-${Date.now()}`);
  let committed = false;
  try {
    mkdir(root);
    const files = listFiles(oldData);
    await copyAll(oldData, tmp, files, onProgress);

    // 校验：数量 + 每本书的源文件大小
    if (countFiles(tmp) !== files.length) throw new Error('复制不完整');
    verifyLibrary(tmp);

    writeMarker(tmp);
    rewriteLibrary(tmp, oldData);      // 绝对路径改写 + 外部书收编
    rename(tmp, dataDir);
    committed = true;

    writePointer(root);                // 失败则删 dataDir，回滚
    if (mode === 'move') writeJson(join(dataDir, 'pending-cleanup.json'), { old: oldData, at: Date.now() });

    return { ok: true, root, dataDir };
  } catch (e) {
    rm(committed ? dataDir : tmp);     // 只删本次产物
    throw e;
  }
}
```

### 7.3 回滚点

| 失败点 | 处理 | 用户数据 |
|---|---|---|
| 目标校验失败 | 不写任何东西 | 原样 |
| 复制中失败（空间不足/权限） | 删 tmp | 原样 |
| 校验不一致 | 删 tmp | 原样 |
| 改名失败 | 删 tmp | 原样 |
| 写指针失败 | 删新 dataDir | 原样 |
| 写 `pending-cleanup` 失败 | 不回滚（数据已在新位置），只记日志 | 新位置可用 |
| 重启后新位置打不开 | 启动回退默认，指针保留原值 | 原数据仍在旧位置（移动模式尚未删） |

### 7.4 崩溃恢复

启动时按顺序：

1. `data\migrating.lock` 存在：
   - 若目标 `data` 完整（有 `library.json` 且文件数匹配）→ 视为已提交，删 lock，继续；
   - 若目标只有 tmp → 删 tmp 与 lock，回退原指针。
2. `data\pending-cleanup.json` 存在：
   - 旧目录路径必须带 `.moqi-data` 或 `library.json`；
   - 旧目录不能是当前数据目录、也不能是它的上级；
   - 满足才删，失败留到下次。

### 7.5 并发与锁

- Electron `requestSingleInstanceLock()` 已保证单实例；迁移期间再开一个实例会被聚焦到已有窗口。
- `migrating.lock` 记录 pid：启动发现 pid 仍存活 → 拒绝迁移并提示「另一个墨栖正在搬数据」。

## 8. 卸载策略

### 8.1 原则

- 默认 **只删程序目录**，数据目录原样保留。
- 「同时删除用户数据」默认 **不勾选**，必须二次确认。
- 只删数据根（`<root>` 或 `<root>\data`），绝不按通配符删 `D:\`、`Documents` 等上级。
- 卸载前记录当前数据路径，展示给用户；用户可先备份。

```nsis
    MessageBox MB_YESNO|MB_ICONEXCLAMATION "确定删除所有书、笔记和阅读进度吗？$\r$\n$UnDataPath$\r$\n$\r$\n这个操作不可恢复。" IDYES +2
    Abort
  ${EndIf}
FunctionEnd
```

卸载 Section 里：

```nsis
${If} $UnDataCheck == ${BST_CHECKED}
  ; 只删带标记的目录
  IfFileExists "$UnDataPath\.moqi-data" 0 +2
    RMDir /r "$UnDataPath"
${EndIf}
Delete "$APPDATA\${APP_NAME_EN}\data-root.txt"
```

> 卸载器读的是数据指针，不是安装时快照：用户在软件里改过位置后，卸载也能找到最新位置。
> `un.` 前缀的函数只在卸载器里有效；自写的卸载页函数建议包在 `!ifdef BUILD_UNINSTALLER` 里，避免安装器那趟报 `unused function`。

### 8.3 卸载边界

| 情况 | 行为 |
|---|---|
| 数据目录在 U 盘/网络盘且当前不可用 | 提示路径不可用，跳过删除 |
| 数据根 = 程序目录或其子目录 | 拒绝删除数据，提示手动处理 |
| 数据根 = 盘符根 / 用户主目录 | 拒绝删除（防误删） |
| 用户勾选删除但目录没有 `.moqi-data` | 只删 `data` 子目录，且要求 `library.json` 存在 |
| 卸载时应用仍在运行 | electron-builder 默认检测并提示关闭 |

## 9. 风险与边界校验清单

### 9.1 边界 Case

| # | Case | 期望行为 |
|---|---|---|
| 1 | 空路径 / 只含空格 | 阻断，提示选择文件夹 |
| 2 | 相对路径 `..\data` | 拒绝（只接受绝对路径） |
| 3 | 路径 > 240 字符 | 阻断，提示换浅目录 |
| 4 | 盘符不存在（Z:） | 阻断，提示插好移动硬盘 |
| 5 | 目标无写权限 | 阻断，提示换目录/管理员 |
| 6 | 目标已存在墨栖数据 | 复用，不覆盖 |
| 7 | 目标已存在非墨栖文件 | 拒绝复用，要求换位置 |
| 8 | 目标 = 当前数据目录 | 提示「已经在这里」，不迁移 |
| 9 | 目标在当前数据目录内部 | 拒绝（防递归复制） |
| 10 | 目标父目录是只读介质 | 拒绝，回退默认 |
| 11 | 磁盘剩余空间 < 数据量 × 1.1 | 迁移前检查，阻断并提示所需空间 |
| 12 | 迁移中拔掉 U 盘 | 复制失败 → 删 tmp → 原数据不动 |
| 13 | 迁移中应用崩溃 | 下次启动检测 `migrating.lock` + tmp，回滚 |
| 14 | 指针文件损坏（乱码/空） | 视为无指针，走默认；日志记录 |
| 15 | 指针指向的目录被删 | 若父目录在 → 重建空数据；否则回退默认并提示 |
| 16 | 数据目录是 OneDrive 同步根 | 警告：同步冲突可能导致 JSON 损坏，建议排除 |
| 17 | 数据目录是网络盘 | 警告：延迟/断线会导致写入失败，允许但提示 |
| 18 | 程序目录与数据目录同一路径 | 拒绝（违反程序目录纯净） |
| 19 | 非管理员装到 Program Files | 拦截，提示换用户目录 |
| 20 | 便携包放只读 U 盘 | 数据回退系统目录，黄条提示 |
| 21 | 便携包盘符变化 | 指针失效 → 回退 `<exeDir>\{{DATA_DIR}}` 并提示 |
| 22 | 两个实例同时迁移 | 单实例锁 + `migrating.lock` 拒绝 |
| 23 | 卸载时数据在移动硬盘未插 | 跳过删除并提示 |
| 24 | 卸载勾选删数据但目录无标记 | 只删 `data` 且有 `library.json` 才删 |
| 25 | 中文/空格路径 | 允许；全程 UTF-8 / `\\?\` 长路径前缀兜底 |
| 26 | 路径含 `CON`/`NUL` 等保留名 | 拒绝 |
| 27 | 迁移到同盘同分区 | 仍走复制+校验（不做 rename，避免半套） |
| 28 | 迁移目标已存在 `data` 但只有空目录 | 视为冲突，拒绝（避免误判） |

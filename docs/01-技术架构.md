# 01 · 技术架构

## 1. 为什么是这套技术

| 候选 | 结论 | 理由 |
|---|---|---|
| **Electron 33** | ✅ 采用 | 主进程直接读本地文件、解析 EPUB/PDF 无跨域问题；Node 生态成熟；打包稳定；Windows 上字体渲染可控 |
| Tauri 2 | ❌ | 体积与内存更优，但需要 Rust 工具链，构建失败风险高；WebView2 在中文排版（标点挤压、避头尾）上弱于 Chromium |
| 纯 Web + 本地文件 | ❌ | 浏览器无法自由读写本地书库，每次都要重新选文件 |
| .NET WPF | ❌ | 中文排版与动效实现成本高，迭代慢 |

**性能认知**：阅读器的流畅度瓶颈在"渲染层排版与滚动"，不在"外壳体积"。Electron 的 Chromium 在中文排版（`text-justify: inter-ideograph`、`line-break: strict`）上是最强的，这一点直接决定阅读观感。

## 2. 进程模型

```
┌─────────────────────────────────────────────────────────────┐
│ 主进程 Main (Node)                                           │
│  · 窗口生命周期、单实例、窗口位置记忆                          │
│  · 文件系统：扫描书库、读文件                                 │
│  · 解析：TXT / EPUB / MOBI / PDF → 统一 Book 模型            │
│  · 持久化：JSON 读写、原子写入、迁移                          │
└──────────────────────────┬──────────────────────────────────┘
                           │ contextBridge（contextIsolation: true）
                           │ 白名单 IPC，无 nodeIntegration
┌──────────────────────────┴──────────────────────────────────┐
│ 渲染进程 Renderer (React)                                    │
│  · 工作台：总览 / 书架 / 笔记 / 分析 / 足迹                    │
│  · 阅读页：渲染 Book、收集输入、管理界面状态                   │
│  · 不接触 fs、不解析文件、不知道 EPUB 存在                     │
└─────────────────────────────────────────────────────────────┘
```

**铁律**：渲染进程**永远**拿到的是已经归一化的 `Book`，不是原始文件。这条保证新增格式时渲染层零改动。

## 3. 数据流

```
① 首次扫描
   磁盘书籍文件夹
      → scanLibrary()            找出所有电子书文件
      → groupByBook()            同名多格式归并为一条记录，选最佳格式
      → 写入 library.json        （只存元信息 + 路径，不存正文）

② 打开一本书
   book.json 已缓存？
      ├─ 是 → 直接读（<300ms）
      └─ 否 → parse(filePath)
                ├─ txt.ts    → 编码检测 → 章节正则 → blocks
                ├─ epub.ts   → unzip → OPF/NCX → xhtml → blocks
                ├─ mobi.ts   → 解包 → html → blocks
                └─ pdf.ts    → pdfjs → outline + 每页文本 → blocks
              → 写入 books/{bookId}/book.json（规范化缓存）
              → 返回 Book 给渲染层

③ 阅读中
   滚动 / 点击 / 选择
      → zustand 内存状态（即时响应）
      → 防抖 400ms → IPC saveProgress / saveNote
      → 主进程原子写入 user/ 下的 JSON

④ 工作台
   启动 → Workspace 挂载
      ├─ useLibrary.load() / scan()        → library.json + 封面
      ├─ ipc.stats.get(120)                → 总览/分析/足迹
      ├─ 遍历 books，ipc.note.list(bookId)  → 全库笔记（主进程没有跨书查询）
      └─ useStats.init()                   → 今日累计（冷启动不显示 0）
   打开笔记 → OpenTarget{chapterId, blockId}
      → App 切到 Reader → 定位并呼吸提示
```

## 4. IPC 通道表

> 改这里必须同步 `electron/preload.ts`、`src/lib/ipc.ts`、本文档。

| 通道 | 方向 | 载荷 | 返回 |
|---|---|---|---|
| `library:scan` | 渲染→主 | `{ force?: boolean }` | `BookMeta[]` |
| `library:list` | 渲染→主 | — | `BookMeta[]` |
| `library:import` | 渲染→主 | `{ paths: string[] }` | `BookMeta[]` |
| `library:remove` | 渲染→主 | `{ bookId, deleteCache }` | `boolean` |
| `book:open` | 渲染→主 | `{ bookId }` | `Book` |
| `book:cover` | 渲染→主 | `{ bookId }` | `string \| null`（dataURL） |
| `book:search` | 渲染→主 | `{ bookId, query }` | `SearchHit[]` |
| `progress:get` | 渲染→主 | `{ bookId }` | `Progress \| null` |
| `progress:save` | 渲染→主 | `Progress` | `boolean` |
| `note:list` | 渲染→主 | `{ bookId }` | `Note[]` |
| `note:save` | 渲染→主 | `Note` | `Note` |
| `note:remove` | 渲染→主 | `{ bookId, noteId }` | `boolean` |
| `note:export` | 渲染→主 | `{ bookId }` | `string`（保存后的路径） |
| `session:add` | 渲染→主 | `ReadingSession` | `boolean` |
| `stats:get` | 渲染→主 | `{ days: number }` | `DailyStat[]` |
| `settings:get` | 渲染→主 | — | `Settings` |
| `settings:save` | 渲染→主 | `Partial<Settings>` | `Settings` |
| `dialog:pickFolder` | 渲染→主 | — | `string \| null` |
| `app:info` | 渲染→主 | — | `{ version, dataDir, libraryDir }` |
| `win:setFullScreen` | 渲染→主 | `{ on: boolean }` | `boolean` |

**命名规范**：`域:动作`。新增通道必须两侧同改，并在上表登记。

> 工作台的全库笔记不是新 IPC：渲染层遍历 `library.json` 的每本书，逐本调 `note:list`，再按 `bookId` 聚合。书多时这是 N 次本地 JSON 读，仍远低于网络/数据库开销；若要优化，再考虑 `note:listAll`。

## 5. 性能策略

| 场景 | 策略 |
|---|---|
| 打开书 | `book.json` 规范化缓存；二次打开直接读缓存 |
| 首屏工作台 | 只加载 `library.json` + 封面缩略图（≤ 40KB 的 dataURL）+ 120 天统计；笔记按书聚合，不阻塞首屏 |
| 章节渲染 | 一次只渲染当前章；相邻章预解析但不挂载 |
| 超长章节 | block 数 > 300 时启用分段挂载（每 80 段一批，IntersectionObserver 触发） |
| 滚动 | 监听用 `passive: true` + `requestAnimationFrame` 节流；进度计算走 `getBoundingClientRect` 缓存 |
| 搜索 | 主进程在 `Book` 上做线性扫描（中文无需分词，直接 `indexOf`），结果限 200 条 |
| 写盘 | 全部防抖 + 原子写（临时文件 + rename） |
| 内存 | 切书时释放上一本的 `Book` 大对象；只保留 1 本 |

## 6. 安全

- `contextIsolation: true`、`nodeIntegration: false`、`sandbox: false`（preload 需要）
- 渲染层加载的章节 HTML **必须消毒**：白名单标签（`p / h1-h6 / blockquote / em / strong / br / img / figure / figcaption / ul / ol / li / table / td / th / tr`），去掉所有 `on*` 属性、`script`、`iframe`、外链
- 图片统一转 `moqi-asset://` 自定义协议本地读取，不暴露真实路径
- 禁用 `webSecurity: false`、禁用 `nodeIntegrationInSubFrames`
- 外部链接一律 `shell.openExternal` 并二次确认

## 7. 依赖清单与理由

| 依赖 | 用途 | 为什么必须 |
|---|---|---|
| `electron` | 外壳 | — |
| `vite` + `@vitejs/plugin-react` | 构建 | 开发热更新快 |
| `react` / `react-dom` | UI | — |
| `typescript` | 类型 | 数据模型复杂，无类型易错 |
| `tailwindcss` | 原子样式 | 与 CSS 变量配合，改样式快 |
| `zustand` | 状态 | 比 Redux 轻，比 Context 快 |
| `framer-motion` | 动效 | 抽屉/标记过渡，手写 CSS 成本更高 |
| `jszip` | 解 ZIP | EPUB 本质是 ZIP |
| `fast-xml-parser` | 解析 XML | 解析 OPF / NCX / container.xml |
| `iconv-lite` + `chardet` | TXT 编码 | 中文 TXT 常见 GBK/GB18030 |
| `pdfjs-dist` | PDF | 唯一成熟的 JS PDF 方案 |
| `mobi` | MOBI 解包 | 轻量，能取出 HTML 与目录 |
| `electron-builder` | 打包 | Windows NSIS 安装包 |
| `concurrently` / `wait-on` | 开发编排 | 同时跑 Vite 与 Electron |

**明确不引入**：任何 UI 组件库、任何图表库、任何状态持久化中间件、任何 markdown 渲染器（暂不需要）。

## 8. 构建链路

```
                      ┌── vite build ──► dist/（渲染层，HTML+JS+CSS）
npm run build ────────┤
                      └── tsc -p tsconfig.electron.json ──► dist-electron/（主进程 + preload）

npm run dist ──► electron-builder ──► release/墨栖 Setup x.y.z.exe
```

主进程用 **tsc 编译**（不用 esbuild 打包），保证 `electron` / `pdfjs-dist` 等原生/大依赖按原样 `require`，避免打包后路径错乱。

# 版本发布说明

每个版本一个文件，**文件名与 git tag 完全一致**：`v0.4.0.md` ↔ `v0.4.0`。

## 用途

- **给用户看**：GitHub / Gitee 的 Release 说明直接从这里复制，两边一字不差。
- **给以后接手的人看**：这一版为什么改、改了什么、有没有需要手动处理的升级动作。

## 与 `CHANGELOG.md` 的分工

| 文件 | 面向谁 | 写什么 |
|---|---|---|
| `docs/CHANGELOG.md` | 开发者 / 未来的自己 | 按版本倒序的流水账，偏向「改了哪些文件、牵连了什么」 |
| `docs/releases/vX.Y.Z.md` | 使用者 | 这一版对他们意味着什么，能做什么新事，要不要做什么 |

两边必须对得上：版本号、日期、功能点一致。发现不一致时，以 `releases/` 为准（那是给用户的承诺）。

## 规则

1. **发版前先写这里，再打包** —— 文档先行。
2. 已发布的版本文件**不再修改**；要更正就发下一个版本。
3. 新建版本时复制 `_template.md`。
4. 打包完成后把文件名、大小、SHA256 补进「文件校验」一节。

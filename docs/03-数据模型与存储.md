# 03 · 数据模型与存储

> **本文档是数据结构的唯一真相。** 任何字段改动必须先改这里，再改 `src/types/models.ts`，再改迁移函数。
> 加字段只能加**可选**字段。改含义、删字段 = 破坏性变更，必须写迁移。

---

## 1. 书籍侧

```ts
type BookFormat = 'epub' | 'mobi' | 'pdf' | 'txt';

/** 书库中的一条记录（轻量，用于书架渲染） */
interface BookMeta {
  id: string;              // 稳定 id：书文件夹名的 hash（见 §5）
  title: string;
  author: string;
  publisher?: string;
  cover?: string;          // 封面文件名（存在 data/books/{id}/ 下），无则 undefined
  format: BookFormat;      // 当前选用的格式

  /** 同一本书拥有的全部格式（用户给了 EPUB+MOBI+PDF+TXT 时会有 4 项） */
  variants: BookVariant[];

  totalChars: number;      // 全书字数（首次解析后回填）
  chapterCount: number;
  addedAt: number;         // 时间戳
  lastOpenedAt?: number;   // 最近打开或切换格式的时间；合并重复条目时用它选活动副本
}

interface BookVariant {
  format: BookFormat;
  path: string;            // 绝对路径
  sizeBytes: number;
  /** 解析质量分：EPUB 100 / MOBI 90 / TXT 80 / PDF 70 —— 分高者被选为默认 */
  quality: number;
}

/** 解析后的完整书籍（大对象，只在内存中保留当前这本） */
interface Book {
  meta: BookMeta;
  chapters: Chapter[];
  /** 扁平目录（保留文件原生 level）；渲染层按 level 建树，存储层不重复存父子 */
  toc: TocItem[];
}

interface Chapter {
  id: string;              // 'c0' / 'c1' / ... —— 序号即 id，稳定
  title: string;
  level: number;           // 1–6，来自文件自带目录，用于建树与缩进
  charCount: number;
  blocks: Block[];
}

type BlockType =
  | 'p'        // 普通段落
  | 'h1' | 'h2' | 'h3' | 'h4'
  | 'quote'    // 引用
  | 'img'      // 图片
  | 'caption'  // 图注
  | 'list'     // 列表（items 存条目）
  | 'hr'       // 分隔
  | 'code';    // 代码块（极少）

interface Block {
  id: string;              // ★ 铁律：`${chapter.id}#${indexInChapter}`，永不可变
  type: BlockType;
  text: string;            // 纯文本（搜索 / 笔记匹配 / 摘录）
  html?: string;           // 含轻量内联标签（em/strong/br/a），渲染用；缺省时用 text
  src?: string;            // img：`moqi-asset://{bookId}/{内部路径}`
  alt?: string;            // img 替代文本
  items?: string[];        // list
  level?: number;          // h1-h4 / 嵌套列表
}

interface TocItem {
  title: string;
  chapterId: string;       // 跳转到哪一章
  blockId?: string;        // 章内锚点（可空 = 章首）
  level: number;           // 1–6
}
```

### 1.1 `blockId` 契约（最高优先级）

```
规则：`${chapterId}#${index}`    例：`c3#17`

为什么用序号而不用 hash：
  · 解析是确定性的，同一文件每次得到相同序号
  · 可读、可调试、体积小

代价：
  · 一旦解析逻辑改变导致段落数变化，旧笔记会错位
  → 因此 04 文档规定「解析逻辑变更必须升 PARSE_VERSION，
     旧缓存失效重建，并对笔记做文本校验兜底」。
```

## 2. 用户侧

```ts
interface Progress {
  bookId: string;

  /** 自动续读位置：随滚动实时更新（防抖 400ms） */
  chapterId: string;
  blockId: string;
  ratio: number;           // 全书进度 0–1（按字数加权）
  updatedAt: number;

  /** ★ "读到此处"手动标记：点段落生成，全书只有一个 */
  mark?: ReadMark;

  /** 分页模式下的页码（仅 paged 模式使用） */
  pageIndex?: number;
}

interface ReadMark {
  chapterId: string;
  blockId: string;
  excerpt: string;         // 该段前 40 字，用于展示与容错定位
  createdAt: number;
  /** 标记时的全书进度，用于"上次读到 37%"提示 */
  ratio: number;
}

interface Note {
  id: string;              // `n_${timestamp}_${rand}`
  bookId: string;
  chapterId: string;
  chapterTitle: string;

  /** 支持跨段落：一个选区可能跨多个 block */
  ranges: TextRange[];

  text: string;            // 选中的原文（跨段时以 \n 连接）
  comment: string;         // 用户想法，可为空（纯高亮）
  color: HighlightColor;

  /** paragraph = 整段笔记；selection = 划词笔记 */
  kind: 'selection' | 'paragraph';

  createdAt: number;
  updatedAt: number;
}

interface TextRange {
  blockId: string;
  start: number;           // 在该 block.text 中的字符偏移（含）
  end: number;             // 偏移（不含）
}

type HighlightColor = 'clay' | 'moss' | 'indigo' | 'amber';

interface ReadingSession {
  id: string;
  bookId: string;
  bookTitle: string;
  date: string;            // 'YYYY-MM-DD'（本地时区）
  startedAt: number;
  endedAt: number;
  seconds: number;         // 净阅读秒数（失焦 >60s 不计）
}

interface DailyStat {
  date: string;
  seconds: number;
  books: { bookId: string; title: string; seconds: number }[];
  noteCount: number;
  pagesRead: number;
}
```

### 2.1 续读规则（对应 05 文档）

```
打开一本书时：
  1. 若 progress.mark 存在 → 不自动跳（用户可能想继续往后读）
  2. 自动定位到 progress.blockId（最新位置）
  3. 顶栏下方浮出 ResumeChip：「上次标记在第 3 章 · 回到那里」
     · 若当前最新位置 == 标记位置 → 不显示 chip
     · 5 秒无操作自动淡出，鼠标移到顶部可召回

用户点击段落 → 设置 mark（覆盖旧的），同时 progress 也更新到该处。
用户往后滚动 → 只更新 progress，不动 mark。
```

## 4. 存储文件布局

| 文件 | 内容 | 写入时机 | 丢失后果 |
|---|---|---|---|
| `data/library.json` | `BookMeta[]` | 扫描/导入/换格式后 | 重新扫描即可恢复 |
| `data/settings.json` | `Settings` | 设置变更后 300ms | 设置回默认 |
| `data/books/{id}/book.json` | `Book` | 首次解析后 | 重新解析（慢几秒） |
| `data/user/progress.json` | `{ [bookId]: Progress }` | 滚动防抖 400ms | 丢续读位置（可接受） |
| `data/user/notes.json` | `{ [bookId]: Note[] }` | 每次增删改立即 | **不可接受 → 必须原子写 + 写前备份 .bak** |
| `data/user/sessions.json` | `ReadingSession[]` | 每次会话结束 | 丢计时（可接受） |

### 4.1 原子写协议（必须照做）

```
写 X.json：
  1. 序列化 → 写入 X.json.tmp
  2. fsync
  3. 若 X.json 存在 → rename 为 X.json.bak
  4. rename X.json.tmp → X.json
  5. 失败则回滚 .bak

读取时：
  若 X.json 解析失败 → 尝试 X.json.bak → 仍失败则用默认值并记录日志
```

## 5. `bookId` 生成规则

```
输入：书籍所在文件夹的绝对路径（去掉盘符，统一小写）
算法：取路径 basename，规范化（去扩展名/去方括号内容/trim），
      再拼接 8 位 md5，形如：
      `fudongchan-3f9a2c1b`

为什么要 basename + hash：
  · basename 可读，方便调试
  · hash 保证同名不同目录的书不会冲突
  · 不依赖文件内容（避免每次改文件 id 变化）

容错：若无法取得文件夹（用户直接拖入单个文件），用文件 basename。
```

## 6. 版本迁移

`settings.dataVersion` 当前为 **2**。

### v1 → v2（2026-11-08）

```ts
// electron/store/userdata.ts · getSettings()
// v1 时代没有「翻页方式」入口，保存的 pageMode: 'scroll' 只是默认值，不是用户选择。
// 升级到 v2 时一次性改为 'paged'，此后用户的手动选择原样保留。
if ((raw.dataVersion ?? 1) < 2) {
  raw.pageMode = 'paged';
  raw.dataVersion = 2;
}
```

### 以后的新增破坏性变更

```ts
// electron/store/migrate.ts
const MIGRATIONS: Record<number, () => void> = {
  3: () => { /* v2 → v3 的具体转换 */ },
};
export function migrate() {
  let v = readVersion();
  while (v < CURRENT_VERSION) { MIGRATIONS[v + 1]?.(); v++; }
  writeVersion(CURRENT_VERSION);
}
```

**迁移必须在 `app.whenReady()` 之前完成，且要写 `.bak`。**

## 7. 个人数据导入导出

> 目标：换电脑、重装系统时，用户自己就能把「读到哪、笔记、阅读时长」搬过去，不需要懂 JSON、不需要手动找路径。

### 7.1 哪些算个人数据

只有 `data/user/` 下的三个文件：

| 文件 | 内容 | 丢了会怎样 |
|---|---|---|
| `progress.json` | 每本书读到哪个位置、进度百分比、手动标记 | 所有书回到未读状态 |
| `notes.json` | 全部划词笔记与整段笔记 | 笔记全丢 |
| `sessions.json` | 每次阅读的时长记录（统计、热力图、年度回顾都靠它） | 所有统计归零 |

**不属于个人数据**：`library.json`（书架索引，重新扫描书文件夹即可生成）、`books/`（解析缓存，可重建）、`settings.json`（界面偏好，跟机器走更合理）。

### 7.2 导出的样子

用户选一个保存位置，在里面新建：

```
墨栖个人数据-2026-11-11/
├── progress.json
├── notes.json
├── sessions.json
└── 导入说明.txt
```

`导入说明.txt` 是给人看的大白话，不参与程序逻辑：

```
这是「墨栖」的个人阅读数据备份。
导出于 2026-11-11 00:30 · 软件版本 0.4.0

怎么恢复：
1. 打开墨栖，点右上角「数据备份」按钮
2. 点「导入我的数据」
3. 选中这个文件夹（选它的上一层也可以），确定
4. 看到「个人数据导入成功」就好了

请不要修改里面的 .json 文件。
```

### 7.3 导入时怎么找数据

用户选中的目录可能是任意一层，必须都认：

| 用户选的是 | 实际情况 | 处理 |
|---|---|---|
| `墨栖个人数据-2026-11-11/` | 三个 json 直接在里面 | 直接用 |
| `data/` | 在 `user/` 子目录里 | 向下找 |
| 某个上层文件夹 | 数据埋在深处 | 向下最多 3 层搜 |
| 只拷了其中一个文件 | 只有部分 | 有几个用几个 |

搜索顺序：当前目录 → `user/` → `data/` → `data/user/` → 广度优先下探 3 层。命中即停，同名文件以最近的为准。

### 7.4 校验规则

三个文件**逐个**校验，只接受合格的那几个；至少要有一个文件含实际数据，否则整包拒绝。

| 文件 | 合格条件 |
|---|---|
| `progress.json` | 对象；每个 value 含 `bookId:string`、`chapterId:string`、`blockId:string`、`ratio:number`、`updatedAt:number` |
| `notes.json` | 对象；每个 value 是数组，每条含 `id:string`、`bookId:string`、`text:string`、`createdAt:number`、`ranges:array` |
| `sessions.json` | 数组；每条含 `id:string`、`bookId:string`、`date:string`（`YYYY-MM-DD`）、`seconds:number` |

返回结构：

```ts
type ImportResult =
  | { ok: true;  counts: DataCounts; merged: DataCounts; backupDir: string }
  | { ok: false; reason: 'not-moqi-data' | 'empty' | 'read-error'; detail: string };
```

界面按 `reason` 显示不同文案（见 `07` 文档 §2.8）。

### 7.5 合并策略：只补不覆盖

导入前，先把现有三个文件复制到 `data/user/_backup-<时间戳>/`，再合并：

| 数据 | 合并规则 |
|---|---|
| `progress` | 按 `bookId` 对齐；`updatedAt` 更新的胜出 |
| `notes` | 按 `note.id` 去重；`updatedAt` 更新的胜出 |
| `sessions` | 按 `session.id` 去重 |

**为什么合并而不是覆盖**：用户可能只从旧电脑带走一部分数据。覆盖会把他这台电脑上已有的记录清掉；合并只会「补上缺的、更新新的」，重复导入也不会产生重复数据。

### 7.6 硬约束

- 只读写 `data/user/`，**绝不碰书籍文件、书架索引、解析缓存**。
- 导入失败时**不写入任何东西**，现有数据保持原样。
- 备份目录不参与任何读取逻辑，只供用户手动回滚。

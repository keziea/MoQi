# 03 · 数据模型与存储

> **本文档是数据结构的唯一真相。** 任何字段改动必须先改这里，再改 `src/types/models.ts`，再改迁移函数。
> 加字段只能加**可选**字段。改含义、删字段 = 破坏性变更，必须写迁移。

## 1. 书籍侧

```ts
type BookFormat = 'epub' | 'mobi' | 'pdf' | 'txt';

/** 书库中的一条记录（轻量，用于书架渲染） */
interface BookMeta {
  id: string;              // 稳定 id：书文件夹名的 hash（见 §5）
  title: string;
  author: string;
  publisher?: string;
  cover?: string;          // 封面文件名（存在 data/books/{id}/ 下），无则 undefined
  format: BookFormat;      // 当前选用的格式

  /** 同一本书拥有的全部格式（用户给了 EPUB+MOBI+PDF+TXT 时会有 4 项） */
  variants: BookVariant[];

  totalChars: number;      // 全书字数（首次解析后回填）
  chapterCount: number;
  addedAt: number;         // 时间戳
  lastOpenedAt?: number;   // 最近打开或切换格式的时间；合并重复条目时用它选活动副本
}

interface BookVariant {
  format: BookFormat;
  path: string;            // 绝对路径
  sizeBytes: number;
  /** 解析质量分：EPUB 100 / MOBI 90 / TXT 80 / PDF 70 —— 分高者被选为默认 */
  quality: number;
}

/** 解析后的完整书籍（大对象，只在内存中保留当前这本） */
interface Book {
  meta: BookMeta;
  chapters: Chapter[];
  /** 扁平目录（保留文件原生 level）；渲染层按 level 建树，存储层不重复存父子 */
  toc: TocItem[];
}

interface Chapter {
  id: string;              // 'c0' / 'c1' / ... —— 序号即 id，稳定
  title: string;
  level: number;           // 1–6，来自文件自带目录，用于建树与缩进
  charCount: number;
  blocks: Block[];
}

type BlockType =
  | 'p'        // 普通段落
  | 'h1' | 'h2' | 'h3' | 'h4'
  | 'quote'    // 引用
  | 'img'      // 图片
  | 'caption'  // 图注
  | 'list'     // 列表（items 存条目）
  | 'hr'       // 分隔
  | 'code';    // 代码块（极少）

interface Block {
  id: string;              // ★ 铁律：`${chapter.id}#${indexInChapter}`，永不可变
  type: BlockType;
  text: string;            // 纯文本（搜索 / 笔记匹配 / 摘录）
  html?: string;           // 含轻量内联标签（em/strong/br/a），渲染用；缺省时用 text
  src?: string;            // img：`moqi-asset://{bookId}/{内部路径}`
  alt?: string;            // img 替代文本
  items?: string[];        // list
  level?: number;          // h1-h4 / 嵌套列表
}

interface TocItem {
  title: string;
  chapterId: string;       // 跳转到哪一章
  blockId?: string;        // 章内锚点（可空 = 章首）
  level: number;           // 1–6
}
```

### 1.1 `blockId` 契约（最高优先级）

```
规则：`${chapterId}#${index}`    例：`c3#17`

为什么用序号而不用 hash：
  · 解析是确定性的，同一文件每次得到相同序号
  · 可读、可调试、体积小

代价：
  · 一旦解析逻辑改变导致段落数变化，旧笔记会错位
  → 因此 04 文档规定「解析逻辑变更必须升 PARSE_VERSION，
     旧缓存失效重建，并对笔记做文本校验兜底」。
```

## 2. 用户侧

```ts
interface Progress {
  bookId: string;

  /** 自动续读位置：随滚动实时更新（防抖 400ms） */
  chapterId: string;
  blockId: string;
  ratio: number;           // 全书进度 0–1（按字数加权）
  updatedAt: number;

  /** ★ "读到此处"手动标记：点段落生成，全书只有一个 */
  mark?: ReadMark;

  /** 分页模式下的页码（仅 paged 模式使用） */
  pageIndex?: number;
}

interface ReadMark {
  chapterId: string;
  blockId: string;
  excerpt: string;         // 该段前 40 字，用于展示与容错定位
  createdAt: number;
  /** 标记时的全书进度，用于"上次读到 37%"提示 */
  ratio: number;
}

interface Note {
  id: string;              // `n_${timestamp}_${rand}`
  bookId: string;
  chapterId: string;
  chapterTitle: string;

  /** 支持跨段落：一个选区可能跨多个 block */
  ranges: TextRange[];

  text: string;            // 选中的原文（跨段时以 \n 连接）
  comment: string;         // 用户想法，可为空（纯高亮）
  color: HighlightColor;

  /** paragraph = 整段笔记；selection = 划词笔记 */
  kind: 'selection' | 'paragraph';

  createdAt: number;
  updatedAt: number;
}

interface TextRange {
  blockId: string;
  start: number;           // 在该 block.text 中的字符偏移（含）
  end: number;             // 偏移（不含）
}

type HighlightColor = 'clay' | 'moss' | 'indigo' | 'amber';

interface ReadingSession {
  id: string;
  bookId: string;
  bookTitle: string;
  date: string;            // 'YYYY-MM-DD'（本地时区）
  startedAt: number;
  endedAt: number;
  seconds: number;         // 净阅读秒数（失焦 >60s 不计）
}

interface DailyStat {
  date: string;
  seconds: number;
  books: { bookId: string; title: string; seconds: number }[];
  noteCount: number;
  pagesRead: number;
}
```

### 2.1 续读规则（对应 05 文档）

```
打开一本书时：
  1. 若 progress.mark 存在 → 不自动跳（用户可能想继续往后读）
  2. 自动定位到 progress.blockId（最新位置）
  3. 顶栏下方浮出 ResumeChip：「上次标记在第 3 章 · 回到那里」
     · 若当前最新位置 == 标记位置 → 不显示 chip
     · 5 秒无操作自动淡出，鼠标移到顶部可召回

用户点击段落 → 设置 mark（覆盖旧的），同时 progress 也更新到该处。
用户往后滚动 → 只更新 progress，不动 mark。
```

## 4. 存储文件布局

| 文件 | 内容 | 写入时机 | 丢失后果 |
|---|---|---|---|
| `data/library.json` | `BookMeta[]` | 扫描/导入/换格式后 | 重新扫描即可恢复 |
| `data/settings.json` | `Settings` | 设置变更后 300ms | 设置回默认 |
| `data/books/{id}/book.json` | `Book` | 首次解析后 | 重新解析（慢几秒） |
| `data/user/progress.json` | `{ [bookId]: Progress }` | 滚动防抖 400ms | 丢续读位置（可接受） |
| `data/user/notes.json` | `{ [bookId]: Note[] }` | 每次增删改立即 | **不可接受 → 必须原子写 + 写前备份 .bak** |
| `data/user/sessions.json` | `ReadingSession[]` | 每次会话结束 | 丢计时（可接受） |
| `data/_backups/{时间戳}/` | library + settings + user 的副本 | 每次导入备份前 | 无（只是安全垫，可随时删） |

### 4.1 原子写协议（必须照做）

```
写 X.json：
  1. 序列化 → 写入 X.json.tmp
  2. fsync
  3. 若 X.json 存在 → rename 为 X.json.bak
  4. rename X.json.tmp → X.json
  5. 失败则回滚 .bak

读取时：
  若 X.json 解析失败 → 尝试 X.json.bak → 仍失败则用默认值并记录日志
```

## 5. `bookId` 生成规则

```
输入：书籍所在文件夹的绝对路径（去掉盘符，统一小写）
算法：取路径 basename，规范化（去扩展名/去方括号内容/trim），
      再拼接 8 位 md5，形如：
      `fudongchan-3f9a2c1b`

为什么要 basename + hash：
  · basename 可读，方便调试
  · hash 保证同名不同目录的书不会冲突
  · 不依赖文件内容（避免每次改文件 id 变化）

容错：若无法取得文件夹（用户直接拖入单个文件），用文件 basename。
```

## 6. 版本迁移

`settings.dataVersion` 当前为 **2**。

### v1 → v2（2026-11-08）

```ts
// electron/store/userdata.ts · getSettings()
// v1 时代没有「翻页方式」入口，保存的 pageMode: 'scroll' 只是默认值，不是用户选择。
// 升级到 v2 时一次性改为 'paged'，此后用户的手动选择原样保留。
if ((raw.dataVersion ?? 1) < 2) {
  raw.pageMode = 'paged';
  raw.dataVersion = 2;
}
```

### 以后的新增破坏性变更

```ts
// electron/store/migrate.ts
const MIGRATIONS: Record<number, () => void> = {
  3: () => { /* v2 → v3 的具体转换 */ },
};
export function migrate() {
  let v = readVersion();
  while (v < CURRENT_VERSION) { MIGRATIONS[v + 1]?.(); v++; }
  writeVersion(CURRENT_VERSION);
}
```

**迁移必须在 `app.whenReady()` 之前完成，且要写 `.bak`。**

## 7. 备份与恢复（v2）

> 目标：换电脑、重装系统时，用户自己就能把「书架 + 读到哪 + 笔记 + 阅读时长 + 书文件」一起搬过去，不需要懂 JSON、不需要手动找路径。

### 7.1 一个包里装什么

备份是一个 ZIP，内部结构与 `data/` 一一对应：

```
墨栖备份-2026-11-20-2140.zip
└── 墨栖备份-2026-11-20-2140/
    ├── manifest.json          机器可读：格式版本、软件版本、数量、是否含书
    ├── 导入说明.txt            人可读：怎么恢复
    └── data/
        ├── library.json        书架（含分类、封面文件名、多格式信息）
        ├── settings.json       只含「跟着人走」的设置：分类、笔记分类颜色、每日目标
        ├── user/
        │   ├── progress.json
        │   ├── notes.json
        │   └── sessions.json
        └── books/{bookId}/
            ├── cover.jpg
            └── source/书名.epub
```

**为什么不带 `book.json`（解析缓存）**：它是派生数据，恢复后第一次打开会自动重建。
带上只会让包大一倍；不带反而更小、更不容易受解析版本变化影响。

**书文件路径**：`source/` 下保留原文件名，方便用户解压后自己认。恢复时复制进
`data/books/{bookId}/source/`，`library.json` 里的 `variants[].path` 改写成新路径。

### 7.2 导出

- 入口：工作台右上角「数据备份与恢复」→「导出为压缩包」
- 保存对话框默认文件名：`墨栖备份-YYYY-MM-DD-HHmm.zip`
- 可选「连书一起打包」（默认勾选）。不勾选时只写 `data/` 下的四类记录，不写 `books/`
- 写完先落 `.part`，成功后改名；中途失败不会留下半个压缩包
- 成功后把时间写进 `settings.lastBackupAt`，面板上显示「今天 / 3 天前备份过」

性能约束：写包是流式的，一个文件一个文件读、压缩、写盘，内存占用与单本书大小相关，
与书库总量无关。单个包上限 4GB（超过时明确提示取消勾选「连书一起打包」）。

### 7.3 导入

两种入口，走同一套逻辑：

| 用户选择 | 处理 |
|---|---|
| `.zip` 文件 | 读中央目录 → 按需流式解出 |
| 已解压的文件夹 | 直接递归读（最多 8 层） |
| `.7z` / `.rar` | 明确提示「先解压成文件夹，或用 ZIP 重新打包」 |

#### 定位数据目录

在文件清单里找 `progress.json`，按优先级：

1. `*/data/user/progress.json`
2. `*/user/progress.json`
3. `*/progress.json`

命中后反推 `dataDir`：`data/user/` 的上一级是 `data/`；`user/` 的上一级就是数据根；
根目录直接放三个 json 的，`dataDir` 视为空（旧版备份）。

`library.json`、`settings.json`、`books/` 都按 `dataDir` 相对定位。
所以下面这些选法都认：

```
选中 墨栖备份-2026-11-20-2140/     → dataDir = 墨栖备份-.../data
选中 墨栖备份-2026-11-20-2140/data → dataDir = 自己
选中 墨栖个人数据-2026-01-01/       → dataDir = 自己，没有 library.json，按旧版处理
```

#### 校验

先全部读进内存并校验，**任何一项不合格都不落盘**：

| 文件 | 合格条件 |
|---|---|
| `progress.json` | 对象；每个 value 含 `bookId/chapterId/blockId:string`、`ratio/updatedAt:number` |
| `notes.json` | 对象；每个 value 是数组，每条含 `id/bookId/text:string`、`createdAt:number`、`ranges:array` |
| `sessions.json` | 数组；每条含 `id/bookId/date:string`（`YYYY-MM-DD`）、`seconds:number` |
| `library.json` | 数组；每条至少含 `id`（合法 bookId）与 `title`；其余字段尽量保留 |
| `settings.json` | 只取 `categories` / `noteCategories` / `dailyGoalMinutes`，其余忽略 |

编码：UTF-8 优先，失败再用 GBK 解一次（兼容记事本另存的老备份）。

#### 落盘顺序

```
1. data/_backups/<YYYYMMDD-HHmm>/   ← 先把当前 library / settings / user 复制一份
2. data/books/{id}/source/          ← 复制书文件 + 封面
3. data/library.json                ← 合并书架
4. data/user/*.json                 ← 合并笔记 / 进度 / 会话
5. data/settings.json               ← 合并分类与目标
```

第 1 步的目录里附一份 `说明.txt`，告诉用户「不对劲就把这几个文件复制回去」。

### 7.4 合并策略：只补不覆盖

| 数据 | 规则 |
|---|---|
| 书架 | 按 `bookId` 对齐；本机已有则保留本机信息，补上备份里的分类、缺失格式、缺失封面 |
| 书文件 | 同名直接覆盖（重复导入不会越导越多），不同名并存 |
| 进度 | 按 `bookId` 对齐，`updatedAt` 新的胜出 |
| 笔记 | 按 `note.id` 去重，`updatedAt` 新的胜出 |
| 会话 | 按 `session.id` 去重 |
| 分类 | 并集；笔记分类按名字合并，颜色冲突时自动换一个没被占用的颜色 |
| 主题 / 字号 / 窗口位置 / 书库目录 | **不恢复**，这些跟机器走 |

**为什么书文件也要复制进 `data/`**：`bookId` 由「书所在文件夹 + 书名」生成。
换台电脑路径变了，id 就变了，进度和笔记会全部对不上。把书放进墨栖自己的目录、
沿用原 id，是让「读到哪里」和「笔记锚点」原样复活的前提。

### 7.5 返回结构与界面

```ts
type BackupRestoreResult =
  | { ok: true;
      sourceKind: 'zip' | 'folder';
      counts: BackupCounts;      // 备份里带进来多少
      merged: BackupCounts;      // 合并后这台电脑一共多少
      booksAdded / booksUpdated / booksSkipped: number;
      bookFiles: number;
      backupDir: string;
      warnings: string[];
      legacy: boolean; }         // 旧版只有三个 json
  | { ok: false; reason: 'unsupported' | 'not-moqi-data' | 'empty' | 'read-error' | 'zip-error'; detail?: string };
```

界面按 `reason` 显示不同文案（见 `07` 文档 §2.8）。

### 7.6 硬约束

- 导入失败时**不写入任何业务数据**；最多留下一个安全备份目录，不影响读取。
- 备份目录 `data/_backups/` 不参与任何读取逻辑，只供用户手动回滚，可随时删除。
- 书文件只从备份里**复制**，绝不移动、绝不删除用户的原文件。
- 同一个 zip 重复导入必须幂等：笔记不重复、书架不重复、书文件不翻倍。

## 8. 数据存放位置

默认在 `%APPDATA%\moqi-reader\data`。用户可以改到任意目录（D 盘、移动硬盘都行），
安装器在**全新安装**时也会问一次。应用内和安装器遵循同一条规则：

```
你选一个目录  →  在里面建 MoQiData 文件夹  →  数据放 MoQiData\data
```

如果选的目录本身就叫 `MoQiData`，直接用它，不再套一层。

### 8.1 指针文件

`%APPDATA%\moqi-reader\data-root.txt`，纯文本一行绝对路径，例如：

```
E://MoQiData
```

- 启动时先读它，再决定 `paths.data()`；所有读写都走这个目录。
- 安装器写的就是这个文件；应用内改位置也写它。两处格式完全一致。
- 删掉这个文件 = 回到默认位置（下次启动生效）。

### 8.2 不可用时的回退

盘符不存在、父目录也没了（移动硬盘拔掉）时：

1. 本次启动退回默认位置 `%APPDATA%\moqi-reader\data`，保证软件能开；
2. `getDataRootInfo().unavailable` 记住原路径，面板上显示「之前设置的位置打不开」；
3. 插回硬盘后重启，自动回到原位置。

只删了 `MoQiData` 文件夹、盘还在的情况不算不可用，启动时会自动重建。

### 8.3 迁移流程

```
1. 目标目录建 MoQiData
2. 把当前 data 逐个文件复制到 MoQiData\.moqi-data-tmp-<时间戳>
3. 核对文件数量；不一致就整体放弃，原数据一个字节都不动
4. 写入 .moqi-data 标记，改名成 MoQiData\data
5. 修 library.json 里的书文件路径：
   · 原本就在 data/books 里的 → 把绝对路径前缀换成新的 dataDir
   · 原本指向外部文件夹的 → 复制一本进 data/books/{id}/source，再改写路径
6. 写 data-root.txt
7. 重启应用
8. 下次启动读 data\pending-cleanup.json，删掉旧位置
```

第 5 步是必须的：`variants[].path` 存的是绝对路径，不换前缀的话，旧目录一删书就打不开；
顺手把外部书复制进来，新位置才真正「自带书」，整个文件夹拷到别的电脑也能直接读。

第 7 步放到下次启动，是为了避开「迁移完成后当前进程还有零星写入」的竞态。
删除有两条硬保护：旧目录必须带 `.moqi-data` 标记或 `library.json`；旧目录不能是
当前数据目录，也不能是它的上级。

### 8.4 冲突与拒绝

| 情况 | 行为 |
|---|---|
| 选到了当前数据目录里面 | 拒绝，提示换一个位置 |
| 选的就是当前数据根目录 | 视为「已经在这里」，不做任何事 |
| 目标 `MoQiData\data` 已有墨栖数据 | 拒绝，绝不覆盖 |
| 目标 `data` 存在但不是墨栖数据 | 拒绝，避免误伤别的软件 |
| 复制中途失败 / 空间不足 | 删掉半成品，原数据不动，报错 |

### 8.5 安装器

`build/installer.nsh` 在「选择安装位置」之后插入一页「选择数据存放位置」：

- 默认 `$DOCUMENTS`，带「浏览...」按钮；
- 页面上直接写明「将创建：`<目录>\MoQiData`」「数据会放在：`<目录>\MoQiData\data`」；
- 点「下一步」才真正建目录、写指针；
- **只在全新安装时出现**：`%APPDATA%\moqi-reader\data` 已存在，或已有 `data-root.txt`，
  就跳过这一页，避免升级时把用户已经改到 D 盘的位置又指回默认。
